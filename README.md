# mark-vector

마크다운 문서 단위로 입력/출력을 주고받는 LLM 클라이언트 웹 앱입니다. 대화의 각 턴(사용자 입력, LLM 응답)은 하나의 완전한 마크다운 문서로 취급되며, 파일시스템에 `.md` 파일로 저장됩니다.

화면은 3단 세로 split 뷰입니다.

- **왼쪽**: `data/projects/`를 반영한 **프로젝트 → 폴더 → 문서** 트리(아래 "프로젝트 · 폴더 · 문서" 참고). 폴더는 하위 폴더를 가질 수 있고, 디스크에는 `conversations/<폴더ID>/`가 프로젝트 폴더 안에 평평하게 있으며 중첩은 `meta.json`의 `parent_id`입니다. 폴더 제목을 비워 두면 첫 사용자 메시지의 첫 줄(앞의 `#`은 빼고, 60자까지)로 채워지고, 만들 때 제목을 적거나 폴더 행의 ⋯ 메뉴 ✎로 바꾸면 이후 메시지로 다시 바뀌지 않습니다.
- **가운데**: 왼쪽에서 선택한 문서를 편집하는 에디터. 문서를 열면 수식 표기(LaTeX/AsciiMath/하이브리드)를, 보낼 수 있는 문서면 거기에 프로바이더/모델/사고 수준/맥락까지 고르는 작은 툴바가 있습니다(상단 버튼 줄을 한 줄로 유지하려고 평소에는 접혀 있고, 오른쪽 끝 ⚙로 엽니다)(프로바이더/모델/사고 수준/맥락은 폴더가 아니라 메시지 단위 설정이고, 수식 표기는 문서의 directive를 따릅니다 — 아래 "모델 목록 & 사고 수준" 참고).
- **탭**: 왼쪽 트리·빠른 열기·링크 등으로 문서를 열면 항상 새 탭으로 열립니다(이미 열린 문서면 그 탭으로 이동). 탭이 둘 이상이면 편집기 위에 탭 줄이 나타나고, 저장하지 않은 탭은 ● 표시가 붙습니다. 탭을 옮겨 다녀도 저장하지 않은 내용은 그대로 남고, 저장된 탭은 돌아올 때 서버에서 최신 내용을 다시 읽습니다. ⌥[ / ⌥](다른 OS는 Alt) 이전·다음 탭, ⌥W 탭 닫기, ⌥O 현재 탭만 남기고 모두 닫기(탭을 오른쪽 클릭하면 그 탭만 남기기), 가운데 클릭으로도 닫습니다(⌘W·⌃Tab은 브라우저가 쓰므로 쓸 수 없음). 열린 탭 목록은 새로고침 후에도 유지됩니다. 분할 보기의 오른쪽 칸에는 탭이 없습니다.
- **오른쪽**: 가운데 편집 중인 내용의 실시간 마크다운 미리보기.

가운데 에디터의 **대화** 버튼을 누르면 현재 편집 중인 내용이 사용자 턴으로 전송되고, LLM 응답이 스트리밍되어 그 파일의 어시스턴트 섹션으로 붙습니다. 초안을 연 채 보내면 그 파일이 그대로 공식 턴이 되고, 이미 완성된 턴에서 보내면 새 `NNNN.md`가 트리에 나타납니다.

문서가 열려 있을 때 점프 키(맥은 `⌃`, 그 외는 `Alt`)를 잠깐(약 0.35초) 누르고 있으면 트리의 문서에 `⌃1`~`⌃9` 배지가 붙고, 그 번호를 누르면 해당 문서가 바로 열립니다 — 1~3은 최근에 연 문서(지금 열린 문서는 빼서, 1은 직전 문서), 4~9는 같은 폴더의 나머지 문서입니다. 그 밖의 문서는 퀵 오픈(`⌘P`/`⌘K`)으로 찾습니다. (`⌥↑`/`⌥↓`는 편집기의 줄 위/아래로 옮기기 키라 앱 단축키로 쓰지 않습니다.)

화면 폭이 700px 이하(휴대폰)일 때는 3단이 아니라 화면 아래 탭(📁 목록 / ✏️ 편집 / 👁 미리보기)으로 한 번에 한 화면만 보여주고, 글자 크기와 버튼/터치 영역을 키워서 좁은 화면에서도 눈에 편하게 읽고 누를 수 있게 했습니다. 문서를 선택하면 자동으로 편집 탭으로 전환됩니다.

- **백엔드**: Python (FastAPI)
- **프론트엔드**: 바닐라 HTML / CSS / JS (빌드 도구, 프레임워크 없음)
- **LLM 프로바이더**: Anthropic, OpenAI, ChatGPT 플랜 (전환 가능한 구조. ChatGPT는 API 키 대신 플랜 로그인)
- **수식 렌더링**: KaTeX (LaTeX) + [asciimath-markdown](https://github.com/iasandcb/asciimath-markdown) (AsciiMath2 → LaTeX 변환은 그 안의 asciimath-parser). AsciiMath2 표준과 그 표준을 구현한 LaTeX → AsciiMath2 변환 파이썬 패키지는 별도 저장소 [asciimath2](https://github.com/iasandcb/asciimath2) (PyPI `asciimath2`) 참고.

    spoken-math.csv       # 공용 수식 말 (처음 읽을 때 backend/app/spoken_math_default.csv로 생성, git에는 커밋되지 않음)

## 요구 사항

- [uv](https://docs.astral.sh/uv/) (Python 버전 및 의존성 관리)
- uv가 Python 3.14를 자동으로 설치/관리하므로 시스템 Python 버전은 무관합니다.

## 설치 및 실행

```bash
cd backend
cp .env.example .env      # API 키 입력
uv sync                    # 최초 1회 (Python 3.14 + 의존성 설치)
uv run uvicorn app.main:app --reload
```

브라우저에서 http://127.0.0.1:8000 접속.

FastAPI가 `frontend/` 디렉터리를 함께 서빙하므로 별도의 프론트엔드 서버나 빌드 과정이 필요 없습니다.

## 모델 목록 & 사고 수준

모델 드롭다운은 하드코딩이 아니라 각 프로바이더의 `/models` API를 실시간으로 호출해 채웁니다(5분 캐시). Anthropic은 반환되는 모델을 그대로 쓰고, OpenAI는 임베딩/음성/이미지/조정(moderation) 등 채팅과 무관한 모델과 날짜가 박힌 스냅샷(`gpt-4o-2024-08-06` 등)을 걸러내고 대표 별칭만 남깁니다(`backend/app/providers/openai_provider.py`의 `_is_current_chat_model`). OpenAI와 ChatGPT 플랜의 기본 모델은 그 목록에 `gpt-6.1-sol`이 있으면 그 모델입니다(`backend/app/providers/registry.py`의 `preferred_default_model`). 없으면 목록의 첫 모델을 고릅니다.

**사고 수준**(기본/낮음/중간/높음 등, 모델마다 다름)도 프로바이더별로 다르게 매핑됩니다.

**기본**은 사고 설정을 아예 보내지 않아 모델 자체의 기본값으로 돌아갑니다. 모델 문서에서 확인한 기본값이 있으면 `기본 (중간)`처럼 괄호에 표시합니다(예: GPT-5.5·Claude Opus 5.5는 중간, Claude Sonnet 5.5·Fable은 높음, GPT-5.1·5.2·5.4와 Claude 4.x는 없음). 표는 `openai_provider.py`/`anthropic_provider.py`의 `_DEFAULT_EFFORT_RULES`에 있고, 표에 없는 모델은 그냥 `기본`으로 나옵니다. 기본값으로도 생각하는 Claude 모델은 생각이 답을 자르지 않도록 `max_tokens`를 64000으로 잡습니다.

- **Anthropic**: 모델 capabilities가 adaptive thinking을 지원하면 `thinking: {type: "adaptive"}`를 켜고, 그 모델이 받는 수준일 때만 `output_config.effort`에 고른 값을 넣습니다(`max_tokens`는 64000). 그 수준을 받지 않으면 effort만 빼고 adaptive thinking은 유지합니다. 예전 모델(thinking type이 `enabled`뿐인 것)만 `budget_tokens`를 낮음 2000 / 중간 8000 / 높음 24000으로 두고 `max_tokens`를 budget + 4096으로 늘리며, 그 모델에 없는 수준은 가까운 budget으로 바꿉니다. 사고 자체를 지원하지 않으면 설정 없이 답합니다.
- **OpenAI**: 공식 API는 Responses API로 보내고, 사고 수준은 `reasoning: {"effort": ...}`입니다(Chat Completions의 `reasoning_effort`가 아님). 선택지는 모델마다 `_EFFORT_RULES`에 적힌 것(`none`/`minimal`/`low`/`medium`/`high`/`xhigh`/`max` 중 일부)이고, 표에 없는 추론 모델은 `low`/`medium`/`high`만 나옵니다. 추론 모델이 아니면(gpt-4o 등) 사고 수준 선택이 꺼집니다. OpenAI 호환 커스텀 엔드포인트만 Chat Completions의 `reasoning_effort`를 그대로 넘기며, 그 서비스가 거부하면 오류가 화면에 표시됩니다.
- **xAI (Grok)**: OpenAI와 같은 Responses API(`https://api.x.ai/v1`)로 보내고, 웹 검색(`web_search`)과 X 검색(`x_search`)을 켭니다. 사고 수준은 `xai_provider.py`의 `_EFFORT_RULES`(grok-4.7·4.6은 낮음~`xhigh`, 기본 높음 / 4.5는 낮음~높음, 기본 높음 / 4.3은 `none`~`xhigh`, 기본 낮음)를 따르고, 표에 없는 모델과 `non-reasoning` 모델은 사고 수준 선택이 꺼집니다. 기본 모델은 `grok-4.7`입니다.

### 프로바이더/모델/사고 수준/맥락은 메시지 단위이고, 수식 표기는 문서 단위입니다

폴더가 아니라 **메시지를 보낼 때마다** 고릅니다. 에디터가 보낼 수 있는 문서(초안 또는 과거 공식 턴)를 표시하고 있을 때, 에디터 상단 툴바(⚙)에 프로바이더·모델·사고 수준·맥락 드롭다운이 나타납니다. 수식 표기 드롭다운(LaTeX/AsciiMath/하이브리드)은 시스템 프롬프트에서도 보이지만, `custom-symbols.csv`·`spoken-math.csv`·Hermes 전사본에서는 숨겨집니다(system.md·공통 시스템 프롬프트에서는 **대화** 버튼이 비활성화됩니다). 같은 폴더 안에서도 턴마다 다른 프로바이더/모델을 쓸 수 있습니다 — 예를 들어 1번 질문은 GPT로, 2번 질문은 Claude로 보내고 같은 스레드에서 이어갈 수 있습니다. 어느 프로바이더가 받든, 맥락으로 넘어가는 이전 턴은 그 텍스트 그대로입니다. 맥락 범위의 기본값은 **이 문서만**(`context_scope: "default"`, 그 파일 안의 라운드만)이고, **같은 폴더**(`sibling`)나 **폴더 + 하위 폴더**(`descendants`)로 넓힐 수 있습니다.

프로바이더·모델·사고 수준·맥락은 **문서마다** 따로입니다. 이미 보낸 턴을 다시 열면 그 턴에 기록된 값이 드롭다운에 채워집니다. 초안에서 드롭다운을 바꾸면 그 선택이 그 초안에 저장되어, 나중에 다시 열어도 유지됩니다. 새 문서와, 한 번도 고르지 않은 초안은 폴더에 이미 보낸 메시지가 있어도 OpenAI(`OPENAI_API_KEY`가 있을 때)와 모델 `gpt-6.1-sol`로 시작합니다. OpenAI가 없으면 목록의 첫 프로바이더와 그 프로바이더의 기본 모델을 고르고, 사고 수준은 기본, 맥락은 이 문서만으로 시작합니다. 폴더 `meta.json`의 `provider`/`model`은 기본값에 쓰이지 않으며, 전송해도 그 값은 바뀌지 않습니다. 수식 변환은 열린 문서의 directive(없으면 그 폴더 `system.md` → 프로젝트 `system.md` → 공통 `system.md` → LaTeX)가 드롭다운을 정하고, LaTeX가 아니면 응답을 AsciiMath2로 변환합니다. 각 공식 턴은 실제로 어떤 설정으로 만들어졌는지도 함께 기록합니다(`meta.json`의 `turns[].provider`/`model`/`reasoning_effort`/`convert_math`/`context_scope`).

폴더 생성(각 프로젝트 행의 "+" 버튼, 또는 폴더 ⋯ 메뉴의 "새 하위 폴더")은 제목만 물어봅니다(비워두면 첫 메시지로 자동 채워짐) — 프로바이더/모델 선택은 첫 메시지를 보낼 때 합니다.

## ChatGPT 플랜으로 쓰기 (API 키 없이)

[Sign in with ChatGPT](https://developers.openai.com/siwc/token-sharing-open-source)로 로그인하면 `OPENAI_API_KEY` 대신 본인 ChatGPT 플랜으로 OpenAI 모델을 쓸 수 있습니다. 프로바이더 드롭다운에 **ChatGPT (내 플랜)**(영어 UI에서는 *ChatGPT (my plan)*)으로 나타나며, 모델 목록은 그 계정이 쓸 수 있는 모델(`/v1/models`의 `visibility: "list"`)입니다. 사용량은 [ChatGPT 설정 → Usage](https://chatgpt.com/settings/usage)에서 확인·제한합니다.

OpenAI는 이 흐름의 redirect를 `http://127.0.0.1` 루프백만 허용하므로 Fly 서버가 콜백을 직접 받을 수 없습니다. 그래서 문서의 "Self-hosted VMs" 절차대로 로컬에서 로그인한 뒤 자격증명을 서버로 옮깁니다.

```bash
cd backend
uv run python -m app.chatgpt_auth login   # 브라우저에서 "Continue" → DATA_DIR/chatgpt/credentials.json (0600)
uv run python -m app.chatgpt_auth push    # Fly 볼륨 /data/chatgpt/로 전송, 로컬 토큰은 삭제
uv run python -m app.chatgpt_auth status  # 확인 / logout: 세션 해지
```

`push` 이후에는 서버가 1시간짜리 access token을 알아서 갱신합니다(refresh token은 갱신마다 교체, 30일 미사용 시 만료 → 다시 `login` + `push`). 로컬에서도 쓰려면 `push` 하지 말고 로컬에 그대로 두면 됩니다 — 같은 refresh token을 두 곳에서 갱신하면 서로를 무효화하므로 한 곳에만 둡니다.

이 경로는 Responses API 전용이라 `store: false`/`stream: true`로 보내며, 웹 검색은 계정/워크스페이스 정책에 따라 동작합니다(`backend/app/providers/chatgpt_provider.py`).

## 오디오 전사 (화자 분리)

폴더 행의 `⋯` 메뉴 → **오디오 전사 (화자 분리)…** 에서 오디오 파일(m4a/mp3/wav/webm/mp4)을 올리거나 브라우저에서 바로 녹음하면, OpenAI `gpt-4o-transcribe-diarize`로 전사하고 화자를 A, B, …로 구분한 마크다운 문서를 그 폴더에 새 초안으로 만듭니다.

```markdown
# 주간회의

> 2026-10-01 09:00 · 32:14 · 화자 3명 · gpt-4o-transcribe-diarize

**A** `00:00` 안녕하세요. 오늘은…

**B** `00:07` 네, 먼저…
```

- 같은 화자의 연속 구간은 한 문단으로 합칩니다. 화자 이름은 편집기에서 `**A**`를 찾아 바꾸면 됩니다. 문서는 일반 초안이라 그대로 LLM에 보내 요약할 수 있습니다.
- **녹음 언어**(자동/한국어/English/日本語)를 지정하면 도중에 다른 언어로 새는 현상이 줄어듭니다. 기본값은 UI 언어이고, 마지막 선택을 기억합니다.
- API 파일 한도는 25MB입니다. 서버는 24MB를 넘는 파일을 ffmpeg로 모노 16kHz 24kbps Opus(시간당 약 11MB)로 압축해 **한 번에** 보냅니다. 나눠 보내면 조각마다 화자 라벨이 달라지기 때문입니다. 브라우저 녹음은 32kbps(시간당 약 14MB)로 녹음합니다.
- `OPENAI_API_KEY`가 필요합니다. ChatGPT 플랜 경로는 전사 API를 지원하지 않습니다.

## 대화로 옆 문서 작성·수정하기

분할 보기에서 **왼쪽은 대화, 오른쪽은 문서**로 두고, 대화에서 요청해 오른쪽 문서를 쓰거나 고칠 수 있습니다. 예: 왼쪽 `001.md`에서 "draft에 있는 질문을 바탕으로 추가 질문 10개를 추가해줘"라고 보내면 오른쪽 `draft.md`에 10개가 들어갑니다.

- 오른쪽에 문서가 열려 있으면 왼쪽 상단에 **✏️ 버튼**이 나타납니다. 켜져 있는 동안(기본) 보내는 메시지에 오른쪽 문서의 현재 내용(저장하지 않은 수정 포함)이 함께 가고, 모델은 요청이 작성·수정일 때만 문서를 고칩니다. 문서에 대한 질문에는 그냥 답합니다. 끄면 문서를 보내지 않습니다.
- 수정은 답이 오는 대로 오른쪽 문서에 **바로 적용**되지만 **저장하지 않은 변경**으로 남습니다. 저장은 직접 합니다. 방금 바뀐 곳은 선택된 채로 보이고, 오른쪽 위의 띠에 몇 곳이 바뀌었는지와 **되돌리기**가 나옵니다(그 메시지로 바뀐 것을 한 번에 원래대로).
- 모델은 답 안에 수정 블록(찾을 글 → 바꿀 글, 끝에 덧붙이기, 문서 전체 다시 쓰기)을 적고, 앱이 그것을 문서에 적용합니다(`frontend/static/js/doc-edits.js`, 백엔드의 `_target_document_prompt`). 도구 호출이 아니라 글로 된 약속이라 ChatGPT 플랜·OpenAI·Claude·Hermes 어느 프로바이더에서나 같습니다. 찾을 글이 문서에 없으면 그 블록은 건너뛰고 띠에 "찾지 못함"으로 알립니다.
- 대화 문서에는 수정 블록 원문이 그대로 남고, 미리보기에서는 "✏️ 옆 문서를 고쳤습니다" 한 줄로 줄여 보여 줍니다.
- 문서는 매 메시지에 통째로 함께 가므로 긴 문서일수록 토큰을 더 씁니다(20만 자까지).

## 받아쓰기 (🎤)

편집기 툴바의 🎤는 말하는 내용을 커서 위치에 실시간으로 받아씁니다. 언어 선택 옆 **엔진 선택**에서 고르고, 그 선택은 브라우저마다 기억합니다. 기본은 지금까지와 같이 무료인 내장 음성 인식입니다.

| 엔진 | 쓰는 곳 | 비용 |
|---|---|---|
| 🌐 내장 | Web Speech API가 되는 브라우저의 **마이크**(데스크톱 크롬·엣지, 사파리, 안드로이드 크롬). 파일 재생에는 쓰이지 않습니다. | 무료 |
| ⚡ OpenAI | 실시간 전사 `gpt-live-transcribe`(WebRTC). ⚡를 직접 고른 마이크와 파일. Web Speech도 Soniox도 없을 때의 다음 선택. | 켜 둔 동안 분당 약 $0.017 (`OPENAI_API_KEY`) |
| ✦ Soniox | 실시간 전사 `stt-rt-v5`(WebSocket). Web Speech가 안 되는 마이크의 기본, 그리고 🌐일 때 파일의 기본. `SONIOX_API_KEY`가 있을 때만 나옵니다. | 실시간 시간당 약 $0.12 |

`SONIOX_API_KEY`가 없으면 Soniox는 선택지에 나오지 않고, 동작은 이전과 같습니다. 그 키는 서버에만 있습니다. 받아쓰기를 시작하면 서버가 Soniox에 짧은 임시 키를 받아 브라우저에 넘깁니다(`POST /api/stt/soniox/key`, `usage_type`은 `transcribe_websocket`, 일회용, 새 연결은 60초 안에, 한 세션은 최대 3시간). 브라우저는 그 키로 `wss://stt-rt.soniox.com/transcribe-websocket`에 직접 붙습니다. 오디오는 이 서버를 거치지 않습니다(`backend/app/routers/stt.py`, `frontend/static/js/soniox-stt.js`). 받아쓰기 언어가 한국어면 힌트는 `ko`이고, EN/JA를 고르면 그 언어입니다. 중간 결과는 그때그때 바꿔 보여주고, 확정된 토큰만 한 번 이어 붙입니다.

Fly (값은 비밀 저장소에 이미 있거나, 없으면 여기에 넣습니다. 저장소나 브라우저에는 적지 않습니다):

```bash
fly secrets set SONIOX_API_KEY=...
```

로컬은 `backend/.env`의 `SONIOX_API_KEY`입니다.

아이폰에서는 애플이 음성 인식을 사파리에만 열어 두어서, 다른 브라우저(Orion 포함)에서는 Soniox가 설정되어 있으면 Soniox로, 없으면 OpenAI로 마이크가 갑니다. 언어 옆 아이콘과 그 툴팁은 기억해 둔 선택이 아니라 지금 실제로 쓰는 엔진과 요금을 보여 줍니다. 파일을 전사하는 동안에는 그 파일의 엔진을 보여 줍니다. OpenAI는 브라우저가 마이크 음성을 OpenAI로 직접 보내고, 서버는 연결 시작만 중계합니다(`frontend/static/js/realtime-stt.js`). 말이 잠깐 멈추면 그 구간이 확정됩니다. 실시간(과금) 마이크 받아쓰기는 OpenAI든 Soniox든 3분 동안 소리가 없으면 비용을 아끼기 위해 꺼집니다. 브라우저 탭을 바꾸거나 마크벡터 안에서 다른 문서를 열어도 받아쓰기는 끄지 않고, 글은 받기 시작한 문서에만 이어 씁니다. 그 문서 탭을 닫으면 멈춥니다. 아이폰 사파리처럼 탭이 가려지면 마이크나 음성 인식을 브라우저가 멈추는 경우에는 세션을 끊지 않고, 그 탭이 다시 보이면 이어서 받습니다. 가려진 동안에는 브라우저가 소리를 주지 않아 그 구간은 받아 적히지 않을 수 있습니다.

**재생하며 전사**(녹음 목록)는 항상 실시간 엔진입니다. 브라우저 음성 인식은 마이크만 들을 수 있어서, 엔진을 🌐 내장으로 두어도 파일은 Web Speech로 가지 않습니다. 🌐이면 Soniox가 있을 때 Soniox이고, 없으면 OpenAI입니다. ⚡를 직접 고르면 파일도 OpenAI입니다. 전사하는 동안 언어 옆 아이콘은 그 파일의 엔진입니다. 일시정지했다가 다시 재생해도, 위치를 옮겨도 이어서 적습니다. 건너뛴 구간은 적지 않고, 뒤로 옮기면 그 부분을 다시 적습니다. 재생 막대와 녹음 목록의 그냥 재생에는 현재 시각/전체 길이가 보이고, `1:23`, `12:05`, `1:02:30` 또는 초(`90`)를 넣고 이동하면 막대를 끈 것과 같은 자리로 갑니다. 길이를 넘거나 시각이 아니면 옮기지 않고 이유를 보여 줍니다. 아이폰에서도 입력칸과 이동 버튼이 손가락으로 눌립니다. 다른 브라우저 탭으로 가거나 다른 문서를 열어도 재생과 전사는 계속되고, 글은 재생을 시작한 문서에만 쌓입니다. 파일 재생에는 3분 무음으로 끄는 장치를 쓰지 않습니다. 강의 녹음은 그 이상 조용할 수 있고, 파일 길이가 비용의 상한입니다. Soniox 임시 키의 세션 상한은 3시간입니다. 아이폰에서 들리는 소리는 미디어 요소로 나가고 세션은 `playback`이라, 운동 앱의 짧은 음성 안내나 Siri·지도 안내는 유튜브 앱처럼 소리를 잠깐 낮췄다가 원래 크기로 돌아옵니다. 그래도 시스템이 재생을 멈추면, 사용자가 일시정지한 것이 아닐 때 안내가 끝난 뒤 이어서 재생합니다. 녹음 목록의 그냥 재생도 같은 세션이고, 잠금 화면에는 제목이 보입니다. 마이크를 쓰는 받아쓰기·녹음·음성 토론은 `play-and-record`를 유지해서 이 재생 세션이 마이크를 끊지 않습니다. 그동안 전사가 `Request timeout`처럼 끊겼으면 그 위치에서 새 임시 키로 다시 붙습니다. 이미 적은 문장은 다시 적지 않고, 재생이 멈춰 있는 동안에는 keepalive로 연결을 유지합니다.

엔진이 둘 이상 되는 브라우저에서는 언어 선택 옆에 엔진 아이콘(🌐 / ⚡ / ✦)이 나타납니다. 닫혀 있을 때의 아이콘과 마우스를 올렸을 때의 요금은 기억된 선호가 아니라 지금 실제로 돌아가는 엔진입니다. 예를 들어 아이폰 Orion에서 🌐을 골라도 Web Speech가 없으면 아이콘은 ✦(Soniox)로 바뀌고, Soniox 키가 없으면 ⚡로 바뀝니다. 기본 기억값은 무료인 내장이고, ⚡를 고르면 OpenAI가 그대로 쓰입니다. 예전에 ⚡를 고른 브라우저에 저장된 `realtime`은 OpenAI로 그대로 읽습니다. 받아쓰는 중에 바꾸면 새 엔진으로 바로 이어지고, 파일을 재생 중이었다면 그 파일을 새 엔진으로 다시 받습니다. Soniox가 보내는 구간 표시 `<fin>`·`<end>`는 글에 넣지 않습니다. 맥의 크롬에서 BlackHole처럼 시스템 소리를 가상 마이크로 넣을 때는, ✦ Soniox와 ⚡ OpenAI가 그 장치를 음성 통화용 에코 제거·음성 분리 없이 엽니다. 크롬 마이크 설정의 레벨 막대는 장치 자체를 보여 주므로 막대가 움직여도, 페이지가 통화 처리된 스트림이나 앞의 빈 채널만 읽고 있으면 Soniox에는 무음이 가고 3분 뒤에 받아쓰기가 꺼집니다. 채널이 여러 개면 트랙의 채널을 직접 읽어 소리가 있는 것만 섞어 16kHz PCM으로 보냅니다. 크롬이 이 사이트의 마이크로 고른 장치(또는 🎙에서 고른 장치)를 그대로 씁니다. 🌐 내장은 크롬이 잠깐 쉬거나 1분 안팎이 지나면 인식기를 스스로 끊는데, 받아쓰기가 켜져 있는 동안 다시 시작하고 이미 적은 문장은 한 번 더 적지 않습니다. 권한을 거절했거나 장치를 열 수 없으면 그 오류를 보여 줍니다. 공용 수식 말의 왼쪽 열(말)은 Soniox에 문맥 용어로 넘어가 그 말을 알아듣는 데 쓰이고, 기호로 바꾸는 일은 지금까지처럼 받아쓴 뒤에 합니다.

## 음성 토론 (🗣)

문서 화면의 🗣를 열면 왼쪽은 말로 하는 토론이고 오른쪽은 지금 연 문서입니다. 너비 700px 미만(아이폰)에서는 대화/문서 탭으로 나뉘고, 입력은 16px, 버튼은 44px입니다. 마이크는 받아쓰기와 같은 ✦ Soniox 경로입니다(임시 키, BlackHole용 캡처, `enable_endpoint_detection`). 화면에 보이는 글에서는 `<end>`·`<fin>`을 빼지만, `<end>`가 오면 그 말을 툴바에서 고른 모델에 보냅니다. `<end>`가 없으면 기본 1.5초(바꿀 수 있음) 동안 새 확정 토큰이 없을 때 보냅니다. 답이 오는 중에 다시 말하면 그 요청을 취소하고, 이어 말한 것과 합쳐 다시 보냅니다. 지금 보내기와 눌러 말하기도 있습니다. 문서를 고쳐 달라고 할 때만 기존 편집 블록으로 오른쪽 문서가 바뀌고, 바뀐 자리는 잠깐 표시되며, 각 수정은 되돌릴 수 있고 저장은 기존 저장과 같습니다. 음성으로 답하지는 않습니다. 긴 문서는 개요와 해당 구간만 보내고, 오래된 턴은 짧게 줄여 최근 턴만 그대로 둡니다. Soniox는 대략 시간당 $0.12이고, 60분이 되면 마이크를 끕니다. 아이폰에서 다른 앱이 소리를 가져가면 세션을 끊지 않고, 이어하기를 누르면 그래프를 깨웁니다. 브라우저 콘솔의 `[discuss]`에 `<end>`/`<fin>`이 실제로 왔는지 남습니다.

### 수식 받아쓰기

받아쓰는 위치가 `$$` 수식 블록 안이면(리모컨 Y, 안경 ↑, 또는 "수식시작"이라고 말해서 엶) 말한 내용을 AsciiMath로 바꿔 씁니다. 변환기는 [asciimath-markdown](https://github.com/iasandcb/asciimath-markdown)의 `spoken-math.js`(0.3.0부터)이고, [scripter](https://github.com/iasandcb/scripter)도 같은 것을 씁니다.

바꾸는 규칙은 왼쪽 트리 맨 위의 **공용 수식 말**(`S` 배지) 문서 하나에 모두 있습니다. 실제로는 `data/spoken-math.csv`이고, 처음 열 때 기본 어휘(`backend/app/spoken_math_default.csv`)로 채워진 뒤로는 이 파일만 씁니다. 한 줄에 `말, 기호` 하나씩(첫 쉼표 앞이 말, 뒤가 기호라서 `과, ,`처럼 기호가 쉼표여도 됨, 기호가 `\n`이면 수식 안 줄바꿈, `$$`이면 `$$`를 친 것처럼 수식 블록을 열거나 닫음, `{1}`·`{2}`가 들어 있으면 순서를 바꾸는 말 — 아래 참고), `#`로 시작하는 줄은 주석, 같은 말이 여러 번 있으면 아래쪽이 이깁니다. 저장하면 바로 다음 받아쓰기부터 적용되고, 다른 브라우저에서도 받아쓰기를 시작할 때 새로 읽어 옵니다. 로그인 없이 읽을 수 있는 `/api/public/spoken-math`로도 공개되어, [scripter](https://github.com/iasandcb/scripter)가 실행할 때 최신 규칙을 받아 갑니다(쓰기는 로그인 필요).

기본 어휘는 [obsidian-publish-asciimath의 kor-math.js](https://github.com/iasandcb/obsidian-publish-asciimath/blob/main/kor-math.js)를 옮겨 온 것에, 소리 내어 말하기 좋은 괄호 말을 더했습니다.

| 말 | 기호 |
|---|---|
| 수식시작 / 수식끝 | 받아쓰는 자리에서 수식 블록을 열기 / 닫기 (리모컨 Y와 같음) |
| 열고 … 닫고 | `(` … `)` |
| 집합 열고 … 집합 닫고 | `{` … `}` |
| 행렬 열고 … 행렬 닫고 | `[` … `]` |
| 다음줄 | `;` (행렬의 다음 행) |
| 영 일 이 삼 사 오 육 칠 팔 구 (공) | `0`~`9` |
| 자연상수, 오일러 | `e` |
| 이고 | 수식 안에서 줄바꿈 |
| A 분의 B | `B / A` (분수, 분모를 먼저 말함) |
| A 오버 B | `A / B` |
| A 에서·부터 … B 까지 | `_ A … ^ B` (적분·합의 아래·위 끝) |
| 시그마 / 소시그마 | `sum` (Σ) / `sigma` (σ) |
| A 으로·로 | `-> A` (극한) |
| 리밋 … 갈 때 | `lim _ ( … )` ("리밋 엔 무한대로 갈 때" → lim₍ₙ→∞₎). 아래첨자 없는 lim은 "극한" |

예: "엑스 승 2 더하기 라지 와이 는 열고 에이 과 비 닫고" → `x ^ 2 + Y = ( a , b )`, "행렬 열고 1 과 2 다음줄 3 과 4 행렬 닫고" → 2×2 행렬.

- 가장 긴 말부터 맞춥니다("라지에이"는 `A`, "집합 열고"는 `{`). 인식기가 한국어 띄어쓰기를 들쭉날쭉하게 하므로 한글 사이 띄어쓰기는 무시합니다.
- 숫자·영문처럼 이미 기호로 받아쓴 것은 그대로 두고, 인식기가 붙인 문장부호(끝의 `.` 등)는 지웁니다(`3.14` 같은 소수점은 유지).
- 인식기가 "에프"·"엑스"를 글자 그대로(`F`, `X`) 적는 경우가 있어, 따로 떨어진 대문자 한~세 글자는 소문자로 바꿉니다(`F(X)` → `f(x)`, `DX` → `dx`). 대문자는 "라지" 뒤에 올 때만입니다("라지 F" → `F`). `sin`처럼 소문자가 섞인 말은 그대로 둡니다(`RR` 같은 기호는 어휘에서 나오므로 영향 없음).
- 한국어는 분모를 먼저("삼 분의 일"), 경계의 조사를 뒤에("영에서") 말해서 AsciiMath와 순서가 다릅니다. 그런 말은 기호에 `{1}`(바로 앞 덩어리)과 `{2}`(바로 뒤 덩어리)를 써서 순서를 바꿉니다: `분의, {2} / {1}`, `에서, _ {1}`. 덩어리는 토큰 하나 또는 열고~닫고로 묶은 괄호 하나이고, 바꾼 결과도 한 덩어리가 됩니다. 예: "적분 영에서 삼 분의 일 까지 엑스 승 이 디엑스" → `int _ 0 ^ ( 1 / 3 ) x ^ 2 dx`, "극한 밑 열고 엔 무한대로 닫고 …" → `lim _ ( n -> oo ) …`. 받아쓰기는 구절 단위로 바뀌므로 "삼 분의 / 일"처럼 그 사이에서 쉬면 짝이 이어지지 않습니다.
- 대문자는 "라지"로 말합니다("라지 에이" → `A`). 원본의 "빅"은 뒤 모음과 연음되어("빅 에이" → [비게이]) 인식이 잘 안 돼 바꿨습니다.
- 원본에서 변수 `e`·`o`였던 "이"·"오"는 숫자 2·5로 바꿨습니다(수식에서는 숫자가 훨씬 흔함). `e`는 "자연상수"나 "오일러"로 말합니다.
- 원본 목록과 다른 점: "피"가 두 번(`p`, `phi`) 있어 나중 것인 `phi`로, "집폐"는 `{`로 잘못 적혀 있어 `}`로 바로잡았습니다.
- 지시문이 없어 LaTeX로 읽히는 문서라도 아직 다른 수식이 없으면, 처음 수식을 받아쓸 때 맨 위에 `<!-- math: asciimath -->`를 넣습니다. 이미 LaTeX 수식이 있거나 `<!-- math: latex -->`라고 밝힌 문서에서는 바꾸지 않고 일반 받아쓰기로 둡니다.

## 게임패드 리모컨으로 실시간 슬라이드

말하는 내용을 받아쓰면서 게임패드 버튼으로 슬라이드를 만들고, 공개 슬라이드쇼를 보는 청중의 화면을 넘길 수 있습니다. 컨트롤러는 **일반 게임패드 모드**로 연결합니다(예: 8BitDo Micro는 **D** 모드). 키보드 모드(K)와 달리 버튼이 편집기에 글자로 입력되지 않아서 받아쓰기 중에도 안전합니다(`frontend/static/js/remote.js`, Gamepad API).

준비:

1. 문서를 발행하고 **🎞 슬라이드**와 **🔴 실시간**을 켭니다.
2. 편집기 툴바에서 받아쓰기(🎤)를 시작하고, 슬라이드를 만들 프로바이더/모델을 골라 둡니다.
3. 컨트롤러를 연결하고 페이지에서 아무 버튼이나 한 번 누르면 툴바에 🎮이 나타납니다. 🎮을 눌러 동작마다 **지정** → 버튼 누르기로 배정합니다(버튼과 스틱/D패드 축 모두 인식).

| 기본 버튼 (8BitDo Micro 표기) | 동작 | 하는 일 |
|---|---|---|
| A | 새 빈 슬라이드 | 정리하지 않고 즉시 `---`를 넣어 빈 새 장을 열고, 청중 화면도 바로 그 빈 장으로 옮깁니다. 이후 받아쓰는 말은 그 장에 쌓입니다. 이미 빈 장이면 아무것도 더하지 않습니다. |
| X | 줄넘김 | 받아쓰는 위치에서 줄을 넘깁니다. 본문에서는 빈 줄을 넣어 문단을 나누므로 슬라이드에서도 줄이 바뀌어 보이고, 수식 블록 안에서는 한 줄만 넘겨 수식의 다음 줄이 됩니다. |
| B | 현재 슬라이드 정리 | 지금 장의 내용(원문, 또는 정리된 슬라이드 + 이어서 받아쓴 원문)을 그 자리에서 슬라이드로 정리합니다. 첫 글자부터 스트리밍으로 써 넣고, 모델의 가장 낮은 사고 수준으로 보냅니다. 청중은 움직이지 않고, 정리하는 동안 말한 내용은 그 아래 새 문단으로 이어집니다. |
| Y | 수식 블록 | 본문에서 누르면 `$$` / 빈 줄 / `$$`로 된 빈 수식 블록을 넣고 커서를 그 안에 둡니다. 이어서 말하는 내용이 수식 안으로 들어가고, 수식 안에서 다시 누르면 닫는 `$$` 뒤 다음 문단으로 빠져나옵니다. 말로 한 수식("x 제곱 더하기 1")은 B로 정리할 때 수식 표기로 바뀝니다. |
| 십자키 ↑ / ↓ | 청중 화면: 이전 / 다음 장 | |
| 십자키 → / ← | 청중 화면: 맨 앞 / 맨 뒤 장 | 맨 뒤로 가면 받아쓰는 장을 다시 실시간으로 따라갑니다. |
| (지정 안 됨) | 마지막 정리 취소 / 다시 만들기 | 필요하면 🎮 설정에서 버튼을 지정합니다. |

기본 버튼 번호는 브라우저의 standard 배열(십자키 12~15, 얼굴 버튼은 위치 기준 0 아래·1 오른쪽·2 왼쪽·3 위)을 가정합니다. 컨트롤러가 다르게 보고하면 🎮 설정에서 한 번 다시 지정하면 됩니다.

받아쓰는 원문은 Live로 청중에게도 실시간으로 보입니다. 청중 화면 위치는 Live 업데이트에 함께 실려 갑니다. 기본은 "받아쓰는 중인 마지막 장"을 따라가는 것이고, 정리(B)는 청중을 움직이지 않고 그 자리에서 슬라이드를 바꿉니다. 리모컨으로 발표하는 동안에는 방금 연 빈 장도 공개 페이지에 표시됩니다(평소에는 빈 장을 건너뜀). 이전/다음/맨 앞으로 특정 장에 멈춘 뒤 마지막 장에서 "다음"이나 "맨 뒤"를 누르면 다시 받아쓰는 장을 따라갑니다. 리모컨을 한 번도 쓰지 않은 Live에는 이 정보가 실리지 않아서, 청중이 각자 장을 넘기는 기존 동작 그대로입니다.

안경 화면(`/glasses/`, 미리보기 칸의 글래스 체크박스)도 문서가 **슬라이드**로 공개되어 있으면 한 장씩 보여 줍니다. 머리글에 `파일명 · 2/5`처럼 장 번호가 붙고, 안경 D패드로 리모컨처럼 발표를 진행합니다: ←/→ 장 넘기기(마지막 장에서 →는 새 빈 장, 리모컨 A), 선택(핀치/탭, Enter) 지금 장 정리(리모컨 B, 머리글에 ✨), ↑ 수식 블록 열기/나가기(리모컨 Y, 머리글에 $$), ↓ 줄넘김(리모컨 X, 머리글에 ↵ — 본문에서는 문단 나눔, 수식 안에서는 한 줄). 받아쓰기가 꺼져 있을 때 커서가 마지막 장 밖에 있으면 줄넘김과 수식은 문서 끝에 들어갑니다. 문서 전체 보기에서는 ↑/↓가 스크롤입니다. 리모컨으로 발표하는 동안에는 청중 화면과 같은 장을 따라갑니다. 슬라이드 옵션을 끄면 다시 문서 전체를 보여 줍니다.

## OpenAI 호환 프로바이더 (Hermes, 자체 호스팅 등)

Anthropic/OpenAI 외에, `/v1/chat/completions`을 그대로 따르는 아무 서비스나(Hermes(Nous), Together, Fireworks, OpenRouter, 로컬 vLLM/Ollama/LM Studio 등) `backend/.env`의 `CUSTOM_OPENAI_PROVIDERS`에 JSON 배열로 추가하면 프로바이더 드롭다운에 그대로 나타납니다. 코드 수정 없이 개수 제한 없이 추가할 수 있습니다.

```
CUSTOM_OPENAI_PROVIDERS=[{"id":"hermes","label":"Hermes (Nous)","base_url":"https://inference-api.nousresearch.com/v1","api_key":"...","models":["Hermes-4-70B"]}]
```

- `id`, `base_url`은 필수, `label`은 없으면 `id`를 그대로 씁니다.
- `models`는 선택입니다 — 지정하면 그 목록을 그대로 쓰고, 생략하면 해당 엔드포인트의 `/v1/models`를 호출해 자동으로 채웁니다(자체 호스팅 서버는 `/v1/models`를 구현 안 했거나 다르게 동작하는 경우가 있어서, 확실하지 않으면 직접 지정하는 걸 추천합니다). OpenAI 공식 API 전용인 "구식 스냅샷/비채팅 모델 걸러내기" 필터는 커스텀 프로바이더에는 적용하지 않습니다 — 다른 서비스는 모델명 규칙이 달라서(예: `-Instruct` 접미사가 있는 정상적인 채팅 모델이 많음) 오히려 잘못 걸러낼 수 있기 때문입니다.
- `api_key`가 없으면 그 프로바이더는 목록에 나오지 않습니다(키가 없는 Anthropic/OpenAI도 같습니다). 인증이 필요 없는 로컬 서버라도 아무 문자열이나 넣어주세요.
- 사고 수준을 켜면 Chat Completions의 `reasoning_effort`를 전달합니다(공식 OpenAI의 Responses API `reasoning.effort`와는 다릅니다) — 그 서비스가 지원하지 않으면 오류가 그대로 표시됩니다.

### 도구 호출 진행 상황 표시

Hermes 같은 에이전트 게이트웨이는 표준 응답 텍스트 외에, 도구를 실행할 때마다 별도의 SSE `event:` 블록으로 진행 상황(`{"tool": ..., "label": ..., "status": "running"|"completed"}`)을 함께 보내는 경우가 있습니다. mark-vector는 openai SDK의 타입 파싱을 거치지 않고 응답 본문을 직접 읽어서, 이런 커스텀 이벤트를 잡아내 에디터 위에 "🔧 label" 형태로 실시간 표시합니다. 최종 답변 텍스트가 오기 시작하면 자동으로 사라집니다. 공식 OpenAI는 웹 검색, Anthropic은 웹 페이지 가져오기를 같은 자리에 `🌐`/`✅`와 함께 표시합니다. 어느 쪽 이벤트도 없는 프로바이더에서는 아무것도 표시되지 않습니다(동작에 영향 없음).

## 프로젝트 · 폴더 · 문서

트리는 **프로젝트 → 폴더 → 문서** 구조이고, 폴더는 하위 폴더를 가질 수 있습니다(디스크의 디렉터리는 평평하고, 중첩은 `parent_id`). 프로젝트는 폴더들을 묶는 상위 단위로, 그 안의 모든 폴더가 공유하는 자체 시스템 프롬프트를 가질 수 있습니다(아래 "시스템 프롬프트" 참고). "+ 새 프로젝트"로 만들고, 각 프로젝트 행의 "+"로 그 프로젝트 안에 폴더를 만듭니다. 프로젝트 삭제는 **그 안의 모든 폴더·문서를 함께 삭제**하는 되돌릴 수 없는 작업이라, 삭제 버튼을 누르면 안에 폴더가 몇 개 있는지 보여주는 확인 창이 뜹니다(`안의 폴더 N개 포함`).

이 기능이 생기기 전부터 있던 세션은 전부 자동으로 `기본 프로젝트`(id: `default`)로 옮겨집니다 — 서버가 `/api/projects`를 처음 응답할 때(주로 앱을 처음 켤 때) `data/conversations/`가 남아 있으면 통째로 `data/projects/default/conversations/`로 옮기고, 이후로는 그 자리에 아무것도 없으므로 다시 실행되지 않습니다(멱등).

## 시스템 프롬프트

시스템 프롬프트는 **공통, 프로젝트, 그리고 폴더 사슬**입니다.

- **공통 시스템 프롬프트**: 왼쪽 트리 맨 위, 프로젝트 목록과 별개로 항상 고정된 "공통 시스템 프롬프트" 항목(`G` 배지). 모든 프로젝트·모든 폴더의 모든 메시지에 적용됩니다. 실제로는 `data/system.md` 파일 하나입니다.
- **프로젝트별 시스템 프롬프트**: 프로젝트 행의 ⋯ 메뉴 **프로젝트 시스템 프롬프트**로 엽니다(트리에 `P` 배지 행은 없습니다). 그 프로젝트 안의 모든 폴더에 적용됩니다.
- **폴더별 시스템 프롬프트**: 폴더를 만들면 그 폴더에 `system.md`가 자동으로 생성됩니다. 트리 행이 아니라 폴더 행 ⋯ 메뉴의 **폴더 시스템 프롬프트**(S 아이콘)로 엽니다(트리 맨 위의 `S` 배지는 공용 수식 말입니다). 중첩된 폴더는 각자 `system.md`를 갖고, 보낼 때는 루트 조상부터 이 폴더까지 순서대로 이어 붙입니다.

셋 다 다른 문서처럼 선택해서 편집·저장할 수 있고(프로젝트·폴더 시스템 프롬프트는 삭제되지 않으며, 공통 프롬프트와 함께 **대화** 버튼도 비활성화됩니다 — 대화 턴이 아니라 설정이기 때문). 메시지를 보낼 때마다 공통 `data/system.md`, 프로젝트 `system.md`, 조상 폴더들의 `system.md`(루트부터), 이 폴더의 `system.md`를 읽어 **그 순서**로 이어붙인 뒤(있는 것끼리만 빈 줄로 구분, 전부 비어 있으면 아무것도 전달하지 않음) 프로바이더별 방식으로 전달합니다.

- **Anthropic**: 별도의 `system` 파라미터로 전달합니다.
- **OpenAI**(공식 API)와 **ChatGPT 플랜**: Responses API의 `instructions`로 전달합니다. OpenAI 호환 커스텀 엔드포인트는 메시지 목록 맨 앞에 `{role: "system", ...}`으로 추가합니다.

기존에 만들어둔 세션(이 기능 이전)도 문서 목록을 조회하는 순간 빈 `system.md`가 자동으로 채워집니다.

## 공용 커스텀 심볼

"공통 시스템 프롬프트" 바로 아래, 왼쪽 트리 맨 위에 항상 고정된 "공용 커스텀 심볼" 항목(`C` 배지)이 있습니다. 실제로는 `data/custom-symbols.csv` 파일 하나이고(기본값은 빈 파일), 계층 구분 없이 앱 전체에 항상 적용됩니다.

각 줄은 `<AsciiMath 토큰>, <LaTeX>` 형식입니다(예: `suu, \sqcup`, `pmf, \text{pmf}`) — [obsidian-publish-asciimath의 custom-symbols.csv](https://github.com/iasandcb/obsidian-publish-asciimath/blob/main/custom-symbols.csv)와 같은 형식입니다.

- **프론트엔드**(AsciiMath2 → LaTeX, `app.js`가 `markdown.js`의 `setCustomAsciiMathSymbols`를 호출): 모든 줄을 그대로 심볼 설정에 등록합니다 — 분류가 필요 없으므로 CSV의 모든 줄이 항상 적용됩니다. 저장하는 즉시(새로고침 없이) 반영됩니다.
- **백엔드**(LaTeX → AsciiMath2, `asciimath2` 변환기): "LaTeX → AsciiMath 자동 변환" 시 이 CSV를 함께 읽어 `asciimath2.Config`의 `custom_macros`/`custom_text` 확장 지점에 반영합니다. 다만 이 방향은 다음 두 형태의 LaTeX만 인식합니다.
  - 인자 없는 단독 매크로: `\sqcup`, `\hookrightarrow`, `\nleq` 등
  - `\text{X}`/`\operatorname{X}`/`\operatorname*{X}` (내용 `X`가 고정된 경우): `\text{pmf}`, `\operatorname*{LIM}` 등
  - 그 외 형태(`\frac{...}{...}` 패턴, 복합 매크로 시퀀스 등)는 이 방향에서는 조용히 무시됩니다 — 프론트엔드 렌더링(수동으로 그 토큰을 직접 입력하는 경우)에는 여전히 적용되고, LLM 응답을 자동 변환할 때만 그 특정 줄의 효과가 없을 뿐입니다.

system.md에 [수식 렌더링](#수식-렌더링)의 `<!-- math: asciimath -->`/`<!-- math: latex -->` directive를 넣으면, 그 지시자가 없는 문서(특히 LLM 응답)를 미리보기에 렌더링할 때도 기본값으로 적용됩니다. 우선순위는 **문서 자신의 directive → 그 폴더 `system.md`의 directive → 프로젝트별 `system.md`의 directive → 공통 `system.md`의 directive → LaTeX(최종 기본값)** 순입니다(조상 폴더의 `system.md`는 이 수식 표기 상속에는 쓰이지 않습니다).

## 여러 브라우저에서 같은 문서 열기

두 컴퓨터(또는 두 탭)에서 같은 문서를 열어 두면, 한쪽에서 저장한 내용이 다른 쪽에 몇 초 안에 반영됩니다. 열린 문서는 탭이 보이는 동안 4초마다, 그리고 창으로 돌아올 때마다 서버에 "그 뒤로 바뀌었는지"를 묻습니다(파일 수정 시각을 버전으로 사용, 바뀌지 않았으면 내용 없이 짧은 응답).

- 이쪽에 저장 안 한 수정이 **없으면**: 저장된 내용을 그 자리에서 반영합니다. 바뀐 부분만 고쳐 쓰므로 커서 위치는 유지됩니다.
- 이쪽에 저장 안 한 수정이 **있으면**: 덮어쓰지 않고 편집기 위에 "다른 곳에서 저장됨 [불러오기] [내 것 유지]"를 띄웁니다. 내 것 유지를 고르면 그 버전에 대해서는 다시 묻지 않고, 이후 저장하면 이쪽 내용이 저장됩니다.
- 둘로 보기의 오른쪽 창도 저장 안 한 수정이 없을 때 같은 방식으로 반영됩니다.
- 답변 생성, 받아쓰기, 슬라이드 정리 중에는 확인을 쉽니다.

## 데이터 저장 방식

프로젝트 하나 = `data/projects/<프로젝트ID>/` 폴더 하나. 폴더(대화) 하나 = 그 프로젝트 폴더 안 `conversations/<폴더ID>/` 디렉터리 하나. 하위 폴더라도 디렉터리를 더 파지 않고, `meta.json`의 `parent_id`만 가리킵니다.

```
data/
  system.md                       # 공통 시스템 프롬프트
  video-jobs.json                 # YouTube 작업 큐 (아래 "YouTube 영상 작업 큐")
  projects/<project-id>/
    meta.json                     # 제목
    system.md                     # 프로젝트별 시스템 프롬프트 (기본 빈 문서)
    conversations/<id>/
      meta.json                   # 제목, parent_id, 마지막으로 쓴 프로바이더/모델/사고 수준/맥락, 공식 턴 목록/순서
      system.md                   # 폴더별 시스템 프롬프트 (폴더마다 자동 생성, 기본 빈 문서)
      0001.md                     # 문서 (공식 턴 또는 초안). 초안도 같은 NNNN.md 번호
      0002.md                     # 다음 번호
      2026-10-16.md               # 마지막 문서가 YYYY-MM-DD.md일 때만, 새 초안이 날짜 이름
      ...
```

각 파일은 온전한 마크다운 문서이므로, 텍스트 에디터로 직접 열어보거나 다른 도구로 재활용할 수 있습니다.

- **공식 턴**(`NNNN.md`)은 질문이 짧고 답변이 긴 경우가 대부분이라, 사용자 입력과 LLM 응답을 별개 문서 두 개로 나누지 않고 **한 파일 안에 `## User` / `## Assistant` 마크다운 헤딩으로 구분**해 담습니다(헤딩은 영어/한국어/일본어 — 메시지를 보낸 시점의 UI 언어를 따르며, 한 파일 안에서도 대화가 이어지는 동안 언어를 바꾸면 라운드마다 다른 언어의 헤딩이 섞일 수 있습니다 — 기존 라운드의 헤딩은 그대로 두고 새 라운드만 그 시점 언어로 붙습니다). 미리보기에서도 그대로 두 개의 섹션으로 보입니다. `meta.json`의 `turns` 목록에 등록되어 있고, LLM에 보낼 대화 맥락(컨텍스트)을 만들 때 이 헤딩을 기준으로 다시 질문/답변으로 분리해서 사용합니다(**대화** 버튼을 누르면 사용자 부분만 먼저 저장되고, 응답이 스트리밍되는 대로 같은 파일에 어시스턴트 섹션이 채워집니다).
  - 이 기능 이전에 만들어진 세션의 기존 턴은 그대로 `NNNN_user.md`/`NNNN_assistant.md` 두 파일 형태로 남아 있습니다 — 기존 파일을 병합하거나 다시 쓰지 않았고, 대화 맥락을 만들 때 옛 형식과 새 형식을 자동으로 함께 처리합니다. 그 세션에서 새로 주고받는 대화부터 한 파일 형식이 적용됩니다.
  - 열려 있는 공식 턴의 내용이 **아직 답변 없는 질문으로 끝나 있으면**(전송이 실패해 답변을 못 받은 경우든, 이미 완성된 라운드 아래에 새 질문을 이어 적은 경우든) **대화** 버튼은 새 턴을 만드는 대신 **그 파일을 이어서 완성**합니다 — 새 질문 바로 뒤에 답변이 붙고, 그 앞의 라운드들은 그대로 보존됩니다.
- **초안**은 "+ 새 문서"(폴더 행의 + 또는 ⋯ 메뉴)로 만든, 아직 전송하지 않은 문서입니다. 파일명은 공식 턴과 같은 `NNNN.md`이고, 그 폴더의 마지막 문서가 `YYYY-MM-DD.md`이면 오늘(이미 있으면 그 다음 날) 날짜 이름입니다. `meta.json`의 `turns`에 없으므로 LLM 컨텍스트에는 포함되지 않으며, 자유롭게 삭제할 수 있습니다.
- **시스템 프롬프트**(`system.md`)는 폴더마다 하나씩 자동 생성되는 특수 문서입니다. 턴도 초안도 아니며, 메시지 전송 시 대화 맥락과 별도로 프로바이더의 시스템 프롬프트로 전달됩니다. 트리 목록에는 나오지 않고 폴더 ⋯ 메뉴로 엽니다.
- 왼쪽 트리에서 어떤 문서든 선택해 가운데 에디터에서 수정한 뒤 **저장**하면 해당 파일이 그대로 덮어써집니다(공식 턴도 예외 없이 덮어쓰기 가능 — 대화 기록을 고정 불변으로 취급하지 않습니다).
- **삭제**(각 문서 행 ⋯ 메뉴의 삭제. `system.md`는 메뉴에 없음)는 초안·공식 턴 모두 가능합니다. 공식 턴을 삭제하면 그 파일뿐 아니라 `meta.json`의 `turns` 목록에서도 빠지므로, 이후 그 세션에서 주고받는 대화의 LLM 컨텍스트(`build_history`)에서도 함께 제외됩니다 — 삭제 버튼을 누르면 이 점을 다시 한번 확인합니다. 새 턴의 파일 번호(`NNNN.md`)는 항상 그 세션에서 지금까지 쓰인 가장 큰 번호 다음 값으로 매겨지므로(초안이나 존재하는 파일 개수가 아니라), 중간 턴을 삭제해 번호에 빈틈이 생겨도 다음에 만들어질 턴이 남아있는 파일과 번호가 겹치지 않습니다. `system.md`는 모든 세션에 반드시 하나 있어야 하므로 유일하게 삭제할 수 없습니다.
- **대화** 버튼은 에디터의 현재 내용으로 공식 턴을 만듭니다. 열려 있던 문서가 **초안**이면 그 파일이 그대로 공식 턴이 됩니다(새 파일을 만들지 않음). 이미 완성된 턴에서 보내면 새 `NNNN.md`를 만들고, 열려 있는 턴이 이미 답변 없는 질문으로 끝나 있으면 그 턴 자체를 이어서 완성합니다(위 참고).
- **이름 변경**(각 문서 행의 ✎ 버튼)은 `system.md`를 제외한 모든 문서(초안·공식 턴 모두)에서 가능합니다. 공식 턴을 리네임해도 역할/순서 정보는 파일명이 아니라 `meta.json`에 저장돼 있으므로 안전하며, 리네임 시 그 기록도 함께 갱신됩니다. 파일명은 `.md`로 끝나야 하고 경로 구분자(`/`)는 쓸 수 없다는 것 외에는 한글·공백 등 자유롭게 허용됩니다.

## 수식 렌더링

KaTeX(LaTeX)와 [asciimath-markdown](https://github.com/iasandcb/asciimath-markdown)(AsciiMath2 → LaTeX 변환 후 KaTeX 렌더링. 변환 자체는 패키지 안의 [asciimath-parser](https://github.com/widcardw/asciimath-parser))를 jsDelivr CDN에서 로드해 사용합니다. 여기서 말하는 AsciiMath는 asciimath.org 원본 표준이 아니라 그 확장인 **AsciiMath2**입니다 — 표준 정의는 [asciimath2의 SPEC.md](https://github.com/iasandcb/asciimath2/blob/main/SPEC.md) 참고. KaTeX는 `index.html`에 `<script>` 태그로(`katex@0.18.4`), asciimath-markdown은 브라우저용으로 `frontend/static/js/markdown.js`가 `asciimath-markdown@0.4.2`를 ES 모듈로 `import`합니다. 둘 다 고정 버전으로 링크되어 있으므로, 실행 환경에 인터넷 접속이 필요합니다(오프라인 환경이라면 해당 파일들을 `frontend/static/vendor/`에 내려받아 로컬 경로로 바꿔주세요).

| 문법 | 종류 | 예시 |
|---|---|---|
| `$...$` | 인라인 수식 (기본 LaTeX, directive로 전환 가능) | `질량 $E=mc^2$ 등가식` |
| `$$...$$` | 블록 수식 (한 줄 또는 여러 줄, 기본 LaTeX, directive로 전환 가능) | `$$ \int_0^1 x^2\,dx = \tfrac13 $$` |
| `\(...\)` | 인라인 수식 (항상 LaTeX) | `질량 \(E=mc^2\) 등가식` |
| `\[...\]` | 블록 수식 (한 줄 또는 여러 줄, 항상 LaTeX) | `\[ \int_0^1 x^2\,dx = \tfrac13 \]` |
| ` ```asciimath ` | 블록 AsciiMath (항상 AsciiMath) | ` ```asciimath\nsqrt(2)/3\n``` ` |
| ` ```math ` / ` ```latex ` | 블록 LaTeX (항상 LaTeX) | ` ```math\n\frac{1}{2}\n``` ` |

`\(...\)`/`\[...\]`는 표준 LaTeX2e 명령이며(LLM들이 `$...$`/`$$...$$`보다 오히려 이쪽을 더 자주 씁니다), AsciiMath 대응 표기가 없으므로 ` ```math ` 펜스처럼 문서의 math directive와 무관하게 항상 LaTeX로 렌더링됩니다.

`$...$`/`$$...$$`가 기본으로는 LaTeX를 뜻하지만, 문서 아무 곳에나(주로 맨 위에) 아래 directive 주석을 넣으면 그 문서 전체에서 `$`/`$$`를 AsciiMath로 해석합니다. 여러 개 있으면 마지막 것이 적용되고, 이 주석 줄 자체는 렌더링 결과에는 나타나지 않습니다(다른 마크다운 뷰어에서 열어도 일반 HTML 주석이라 보이지 않습니다).

```
<!-- math: asciimath -->
```

```
<!-- math: latex -->
```

세 번째로 `hybrid`가 있습니다 — `$...$`/`$$...$$`는 `asciimath`와 똑같이 AsciiMath지만, `\(...\)`/`\[...\]`는 (원래부터 그렇듯) 항상 LaTeX라는 점을 **의도적으로 활용**하는 모드입니다: 같은 문서 안에서 어떤 수식은 `$`로, 어떤 수식은 `\(`로 써서 두 표기를 나란히 섞어 쓰겠다는 선택이고, "LaTeX → AsciiMath2 자동 변환"도 이 구분을 그대로 지킵니다(아래 참고).

```
<!-- math: hybrid -->
```

에디터 상단 수식 표기 드롭다운(LaTeX/AsciiMath/하이브리드)으로 현재 문서의 방식을 바로 바꿀 수 있고, 전환 시 필요하면 기존 수식도 함께 변환됩니다(AsciiMath2 ⇄ LaTeX 변환에 대한 안내는 아래 "LaTeX → AsciiMath2 자동 변환" 참고 — 하이브리드로 전환할 땐 `$`/`$$` 수식만 변환되고 `\(`/`\[` 수식은 그대로 남습니다).

` ```asciimath `/` ```math ` 펜스 블록은 이미 명시적이라 directive와 무관하게 항상 그대로 동작합니다.

인라인 AsciiMath 전용 구분자(`%...%`)는 제공하지 않습니다 — "10%에서 20%로" 같은 평범한 백분율 표기와 충돌하기 쉬워서, directive로 문서 전체의 `$` 의미를 바꾸는 방식으로 대체했습니다.

블록 수식에 여러 줄을 쓰면 dialect에 따라 다르게 처리됩니다.

- **LaTeX**(기본값)에서는 각 줄이 실제 줄바꿈으로 분리되고 가운데 정렬되어 렌더링됩니다(내부적으로 KaTeX의 `gathered` 환경 사용). 빈 줄은 무시됩니다.
- **AsciiMath2**에서는 AsciiMath2 자체의 정렬 문법을 그대로 씁니다 — 빈 줄이 행(row) 구분자이고, 각 행 안의 `&`는 정렬 마커로 그대로 전달됩니다([asciimath2 SPEC.md](https://github.com/iasandcb/asciimath2/blob/main/SPEC.md) 2.2절). 전체 블록을 한 번에 asciimath-parser에 넘기므로 `\begin{aligned}`/행렬(`[a,b;c,d]`) 구조가 그대로 살아납니다. 빈 줄이 없는 단일 표현식은 이전과 동일하게 한 줄로 렌더링됩니다.

`$$`/`\[`/`\]` 여는·닫는 마커는 그 줄에 단독으로 있지 않아도 됩니다 — LLM이 자주 쓰는 `\[A=\n\begin{bmatrix}...\end{bmatrix}\]`처럼 마커 바로 뒤/앞에 내용이 붙어 있어도 블록으로 인식합니다.

파싱에 실패한 수식은 오류를 표시할 뿐 전체 렌더링을 막지 않습니다.

### LaTeX → AsciiMath2 자동 변환

LLM이 직접 AsciiMath를 생성하면 품질이 떨어지는 경우가 많습니다(학습 데이터에 LaTeX가 압도적으로 많아서). 그래서 메시지를 보낼 때 전송 툴바의 수식 표기 드롭다운에서 **AsciiMath** 또는 **하이브리드**를 선택해두면, LLM에게는 평소처럼 LaTeX로 답하게 하고 — 응답이 저장되기 직전에 서버(`backend/app/latex_to_asciimath.py`, [`asciimath2`](https://github.com/iasandcb/asciimath2) 패키지 사용)가 수식을 하나씩 AsciiMath2로 변환을 시도합니다. **LaTeX**를 선택해두면 변환 없이 LLM 응답 그대로 저장됩니다.

- **AsciiMath** 선택 시: `$...$`/`$$...$$`/`\(...\)`/`\[...\]` 안의 수식을 전부 변환 대상으로 삼습니다. 성공한 것은 `$...$`/`$$...$$`(AsciiMath2)로 바뀌고, 문서 맨 위에 `<!-- math: asciimath -->`가 자동으로 붙습니다. 행렬·정렬 수식(`\begin{pmatrix}`, `\begin{aligned}` 등)도 변환됩니다 — `asciimath2`가 이런 구문을 지원하는 것이 이전에 쓰던 `py-asciimath`와 갈아탄 이유입니다.
- **하이브리드** 선택 시: `$...$`/`$$...$$` 안의 수식만 변환 대상으로 삼고, `\(...\)`/`\[...\]`는 변환을 시도조차 하지 않고 원본 LaTeX 그대로 둡니다 — LLM이 어느 표기를 썼는지에 따라 결과물이 두 표기로 자연스럽게 나뉩니다. 문서 맨 위에는 `<!-- math: hybrid -->`가 붙습니다.
- (두 모드 공통) 변환에 **실패**하면(asciimath2가 지원하지 않는 구문 — [asciimath2 README](https://github.com/iasandcb/asciimath2#readme)의 "Scope, honestly" 참고) 원본 LaTeX를 `\(...\)`/`\[...\]`로 남겨서 — directive와 무관하게 항상 LaTeX로 렌더링되므로 — 깨지지 않고 그대로 보입니다.
- 그 외에 조용히 틀린 결과를 내는(에러 없이) 경우까지는 자동으로 잡아내지 못합니다 — 이건 알려진 잔여 위험입니다.

문서의 수식 표기가 LaTeX가 아니면 응답을 변환하고, LaTeX면 변환하지 않습니다. 표기는 메시지마다 따로 기억하지 않고 열린 문서(와 상속 directive)를 따릅니다(위 "프로바이더/모델/사고 수준/맥락은 메시지 단위이고, 수식 표기는 문서 단위입니다" 참고).

## YouTube 영상 작업 큐

녹음을 받아쓰는 영상으로 만들어 YouTube에 올리는 일은 [scripter](https://github.com/iasandcb/scripter)가 사용자 맥북에서 합니다. 맥은 오래 꺼져 있을 수 있으므로 **마크벡터가 맥을 호출하지 않습니다.** 맥의 워커가 이 큐를 주기적으로 끌어 갑니다(pull). 워커가 둘(나중 맥 한 대 더)이어도 같은 녹음을 둘이 집지 않도록, 가져가기는 원자적이고 리스(lease)가 있습니다.

배포는 기존 GitHub Actions → Fly입니다. 새 서비스나 데이터베이스는 없고, 큐는 `/data/video-jobs.json` 한 파일입니다(`published.json`과 같은 방식, 잠금은 `/data/video-jobs.lock`).

### 어떤 녹음이 큐에 들어가는가

**이미 디스크에 있는 녹음은 넣지 않습니다.** 이 기능 이후의 새 녹음만, 그리고 사용자가 직접 넣은 녹음만 대기합니다.

- 받아쓰기 녹음은 업로드가 끝난 뒤에 앱이 큐에 넣습니다. 녹음 도중 탭이 죽거나 업로드를 포기한 부분 파일은 들어가지 않습니다.
- 문서 ⋯ → 녹음(녹음이 하나도 없어도 열림)에서 **음성 파일 올리기**로 m4a, mp3, wav, webm, ogg, opus, aac, flac, mp4를 그 문서의 녹음으로 올립니다. 로그인 세션이고, 기본으로 큐에 넣습니다. `enqueue=false`면 ingest와 같이 넣지 않습니다.
- `POST /api/ingest/audio`는 파일이 통째로 있으므로 기본으로 큐에 넣습니다. 폼 필드 `enqueue`가 `false` / `0` / `no` / `off`이면 넣지 않습니다.
- 문서의 녹음 목록(트리에서 문서 ⋯ → 녹음)에서 **YouTube 대기열에 넣기** / **대기열에서 빼기** / **다시 시도**를 누를 수 있습니다. 같은 동작이 로그인 세션의 API입니다.

```
PUT /api/projects/{project_id}/conversations/{conv_id}/documents/{filename}/recordings/{recording_id}/video
Content-Type: application/json
Cookie: mv_session=...          # 앱 로그인. WORKER_TOKEN으로는 열 수 없습니다.

{"enqueue": true, "duration_sec": 95.2}     # duration_sec는 생략 가능
{"enqueue": false}                          # 대기·실패·취소만 뺄 수 있음
```

응답은 `{"video": null}` 또는 아래 사용자용 요약입니다. `GET` 같은 경로의 녹음 목록 각 항목에도 `video`가 붙습니다(없으면 `null`).

```json
{
  "job_id": "…",
  "status": "queued",
  "attempt": 0,
  "progress": null,
  "error": null,
  "youtube_video_id": null,
  "youtube_url": null,
  "transcript": null,
  "updated_at": "2026-10-21T01:00:00+00:00"
}
```

`enqueue: true`는 아직 없는 녹음에 작업을 만들고, `cancelled`/`failed`는 다시 `queued`로 되돌립니다. 이미 `queued`/`claimed`/`succeeded`이면 그대로 둡니다(대기 중일 때만 `duration_sec`를 고칩니다). `enqueue: false`는 대기·실패·취소를 `cancelled`로 바꿉니다. 작업이 없으면 `{"video": null}`입니다. 워커가 쥐고 있는 작업(`claimed`)은 409 `Job is in progress`, 이미 성공한 작업은 409 `Job already succeeded`입니다. 빈 파일은 400 `Recording is empty`입니다.

### 워커 인증

`Authorization: Bearer $WORKER_TOKEN`. `INGEST_TOKEN`과 **다른** 비밀입니다. 올리는 권한과 영상을 만들어 공개하는 권한을 나누기 위해서입니다.

Fly:

```bash
fly secrets set WORKER_TOKEN="$(openssl rand -hex 32)"
```

로컬은 `backend/.env`의 `WORKER_TOKEN`입니다. 변수가 비어 있으면 `/api/worker/`는 통째로 **404**입니다(ingest와 같음). 토큰이 없거나 틀리면 **401** `{"detail":"Invalid token"}`입니다. 로그인 쿠키와는 무관하고, 로그인이 켜져 있어도 이 토큰만 있으면 워커 경로를 호출할 수 있습니다.

시각은 모두 UTC ISO 8601(`2026-10-21T01:00:00+00:00`)입니다. `created_at`만 예외로, 녹음 id에 박힌 시작 시각(녹음한 쪽의 벽시계)을 `INGEST_TIMEZONE`(기본 `Asia/Seoul`)으로 해석한 뒤 UTC로 저장한 값입니다.

### 상태와 리스

| status | 의미 |
|---|---|
| `queued` | 워커를 기다리는 중. 목록의 기본값(`waiting`)이 이것입니다. |
| `claimed` | 어떤 워커가 리스를 쥐고 처리 중. |
| `succeeded` | YouTube id/URL이 기록됨. 전사 텍스트가 있을 수 있습니다. |
| `failed` | 워커가 실패를 보고함. 다시 시도하기 전까지 대기열에 없습니다. |
| `cancelled` | 사용자가 뺐습니다. |

리스의 기본은 **3600초**, 허용 범위는 **30초~86400초**(24시간)입니다. 기한이 지난 `claimed`는 다음 읽기(목록, 단건, 가져가기, 진행, 완료, 실패, 오디오, 재시도, 녹음 목록)에서 `queued`로 돌아갑니다. 진행 보고(`progress`)는 리스를 그 시점부터 다시 셉니다(본문의 `lease_seconds`가 있으면 그 길이, 없으면 가져갈 때 정한 길이). 기한이 지난 뒤의 진행/완료/실패/다운로드는 **409** `{"detail":"Job is not held by this claim"}`이고, 그 작업은 다른 워커가 가져갈 수 있습니다. 죽어서 실패를 못 보낸 워커의 작업은 그래서 다시 대기열이 됩니다. `fail`은 "처리했는데 안 됐다"일 때만 쓰고, 그러면 `retry` 또는 사용자의 다시 넣기 전까지 대기하지 않습니다.

`attempt`는 가져간 횟수입니다. 만료로 돌아온 작업을 다시 가져가면 1 오릅니다.

가져가기는 항상 `created_at`이 가장 오래된 대기 작업 하나입니다. 파일이 없으면 그 작업을 `failed`(`error`: `Recording file is missing`)로 두고 다음 것으로 넘어가서, 하나 때문에 큐가 막히지 않습니다.

### `GET /api/worker/jobs`

대기 중인 녹음 목록.

쿼리: `order`=`oldest`(기본)|`newest` (`created_at` 기준), `status`=`waiting`(기본)|`queued`|`claimed`|`succeeded`|`failed`|`cancelled`|`all`, `limit`=1~500.

```json
{
  "jobs": [
    {
      "id": "job id (32 hex)",
      "status": "queued",
      "title": "talk",
      "filename": "talk.md",
      "recording_id": "20261018-193012-ab12.m4a",
      "project_id": "…",
      "project_title": "youtube",
      "conv_id": "…",
      "folder_title": "2026-10-20",
      "mime": "audio/mp4",
      "duration_sec": 95.2,
      "created_at": "2026-10-18T10:30:12+00:00",
      "enqueued_at": "2026-10-21T01:00:00+00:00",
      "updated_at": "2026-10-21T01:00:00+00:00",
      "attempt": 0,
      "worker_id": null,
      "lease_expires_at": null,
      "progress": null,
      "error": null,
      "result": null,
      "audio_url": "/api/worker/jobs/<id>/audio"
    }
  ]
}
```

`duration_sec`는 모를 때 `null`입니다. `mime`는 원본 컨테이너(`audio/webm`, `audio/mp4`, `audio/ogg`)입니다. `title`은 문서 파일명에서 `.md`를 뺀 것입니다. 이 응답에는 `claim_token`이 없습니다. `progress`는 `{"message": string|null, "percent": 0~100|null}`이고, 둘 다 없으면 `null`입니다.

### `POST /api/worker/jobs/claim`

가장 오래된 대기 작업 하나를 원자적으로 집습니다. 빈 큐는 작업이 `null`입니다. 둘 이상의 워커가 동시에 호출해도 서로 다른 작업을 받거나 `null`을 받습니다.

```json
{"worker_id": "macbook-pro", "lease_seconds": 3600}
```

`worker_id`는 1~64자(제어 문자 없음)이고 필수입니다. `lease_seconds`를 생략하면 3600입니다.

응답의 `job`은 목록의 작업 객체와 같고, `status`는 `claimed`이며 **여기만** `claim_token`이 더 있습니다.

```json
{
  "job": {
    "id": "…",
    "status": "claimed",
    "claim_token": "url-safe token",
    "worker_id": "macbook-pro",
    "attempt": 1,
    "lease_expires_at": "2026-10-21T02:00:00+00:00",
    "audio_url": "/api/worker/jobs/<id>/audio"
  }
}
```

(위의 필드는 일부입니다. 목록과 같은 나머지 필드가 모두 함께 옵니다.)

빈 큐:

```json
{"job": null}
```

`claim_token`은 **이 응답에만** 있습니다. 잃어버리면 리스가 끝날 때까지 그 작업을 완료하거나 실패로 보고할 수 없습니다.

### `GET /api/worker/jobs/{id}`

작업 하나. 모양은 목록의 원소와 같고 `claim_token`은 없습니다. 없으면 404 `{"detail":"Job not found"}`.

### `GET /api/worker/jobs/{id}/audio`

리스를 쥔 워커에게만 원본 녹음 바이트를 줍니다. 헤더 `X-Claim-Token: <claim_token>`. `Content-Type`은 `mime`, 파일명은 `{title}-{recording_id}`입니다. 토큰이 없거나 틀리거나 리스가 끝났으면 409 `Job is not held by this claim`. 성공 뒤나 실패 뒤에는 더 이상 claimed가 아니므로 같은 409입니다. 워커는 가져간 직후, 처리가 끝나기 전에 받으면 됩니다.

### `POST /api/worker/jobs/{id}/progress`

처리 중 상태. 리스를 갱신합니다. `message`(최대 500자)와 `percent`(0~100 정수) 중 적어도 하나. `lease_seconds`는 생략 가능.

```json
{"claim_token": "…", "message": "transcribing", "percent": 40}
```

응답은 갱신된 작업 객체(`claim_token` 없음)입니다. 리스를 안 쥐고 있으면 409.

### `POST /api/worker/jobs/{id}/complete`

성공. 리스가 살아 있고 토큰이 맞을 때만.

```json
{
  "claim_token": "…",
  "youtube_video_id": "abcdefghijk",
  "youtube_url": "https://youtu.be/abcdefghijk",
  "transcript": "고친 전사 전문. 생략 가능"
}
```

`youtube_video_id`는 영문·숫자·`_`·`-` 6~64자이고 필수입니다. `youtube_url`을 생략하면 `https://www.youtube.com/watch?v={id}`를 저장합니다. 주면 `http`/`https` URL이어야 합니다. `transcript`는 생략 가능하고, 빈 문자열이면 `null`로 저장합니다(최대 2,000,000자). 전사 본문은 문서 파일을 덮어쓰지 않고 작업에만 남으며, 녹음 목록에서 접어 보여 줍니다.

응답 작업의 `status`는 `succeeded`이고 `result`는 다음과 같습니다.

```json
{"youtube_video_id": "abcdefghijk", "youtube_url": "https://youtu.be/abcdefghijk", "transcript": "…"}
```

그 전에는 `result`가 `null`입니다.

### `POST /api/worker/jobs/{id}/fail`

```json
{"claim_token": "…", "error": "scripter crashed"}
```

`error`는 1~4000자. 응답의 `status`는 `failed`이고 `error`에 그 문자열이 있습니다. 대기 목록에서는 빠집니다.

### `POST /api/worker/jobs/{id}/retry`

본문 없음. `failed`만 `queued`로 되돌립니다. 그 외 상태는 409 `Only a failed job can be retried`. 파일이 없으면 409 `Recording file is missing`. 사용자의 다시 시도(`PUT .../video` `{"enqueue": true}`)도 실패·취소된 작업을 같은 대기 상태로 되돌립니다.

문서·폴더·프로젝트를 지우거나 녹음을 지우면 그 작업도 지워집니다. 문서를 바꾸거나 다른 폴더로 옮기면 작업의 `filename` / `conv_id` / `project_id`가 따라가서, 이미 발급한 `audio_url`로 계속 받을 수 있습니다.

### 워커가 돌리는 순서

1. `GET /api/worker/jobs` (기본: 오래된 순의 대기 작업). 비어 있으면 수십 초 뒤에 다시 봅니다. 맥이 잠들어 있는 동안은 큐가 쌓여 있습니다.
2. `POST /api/worker/jobs/claim`. `job`이 `null`이면 1로.
3. `GET job.audio_url`에 `X-Claim-Token`.
4. 처리하면서 `POST .../progress` (긴 영상이면 리스가 끊기지 않게).
5. 성공이면 `POST .../complete`, 실패면 `POST .../fail`. 다시 할 실패는 `POST .../retry`.

## X 아티클로 내보내기

편집기 상단 **𝕏 X 아티클**에서 현재 편집 중인 문서를 X 아티클 초안으로 보냅니다. 저장 전 수정도 포함하며, 인라인 대화는 펼쳐져 있어도 제외합니다. 먼저 제목과 변환 결과를 확인하고 **X에 초안 만들기**를 누릅니다. 그 뒤 **X 아티클 열기**를 눌러 X의 아티클 목록에서 해당 제목의 초안을 선택하고 편집·공개 발행을 마무리합니다. 마크벡터의 발행/공유 링크는 생성하지 않으며, 이후 원본 문서 수정은 X에 자동 반영되지 않습니다.

X API 호출은 초안 생성 한 번으로 끝납니다. 공개 발행 API 경로와 버튼은 제공하지 않습니다. 2026-10-29 확인한 [X 공식 요금표](https://developer.x.com/?lang=en)의 `Article: Draft` 단가 기준, 정상 전송 한 편당 **$0.01**입니다. X 웹에서 직접 발행하므로 별도 `Article: Publish` API 호출 비용은 없습니다. X 구독료, 세금, 결제 수수료는 별도입니다.

### API 자격증명 설정

X 개발자 앱에서 **Read and Write** 권한을 켜고, 발행할 계정의 OAuth 1.0a 사용자 Access Token/Secret을 발급합니다. 권한을 바꾼 뒤에는 사용자 토큰을 다시 발급해야 할 수 있습니다. 서버의 `backend/.env`에 다음 네 값을 설정하고 서버를 재시작합니다(Fly에서는 같은 이름의 secrets 사용).

```dotenv
X_API_KEY=...
X_API_SECRET=...
X_ACCESS_TOKEN=...
X_ACCESS_TOKEN_SECRET=...
```

이 키는 Grok용 `XAI_API_KEY`와 별개입니다. 자격증명은 서버에서만 사용하며 브라우저에 전달하지 않습니다. 이 앱은 개인용 공유 작업 공간이므로 앱 접근 권한이 있는 사용자는 모두 **서버에 설정한 하나의 X 계정**으로 내보냅니다.

대안으로 `tweet.read tweet.write users.read` 권한이 있는 **OAuth 2.0 사용자 컨텍스트** 토큰을 `X_USER_ACCESS_TOKEN`에 설정할 수 있습니다. 앱 전용 Bearer Token은 발행 권한이 없습니다. OAuth 2.0 사용자 토큰은 만료되면 직접 갱신해야 하며, 네 개의 OAuth 1.0a 값이 모두 있으면 그쪽을 우선 사용합니다. 발행 계정은 X 아티클 이용 자격이 있어야 하며, API 접근 권한·크레딧도 별도로 필요할 수 있습니다. [X 아티클 안내](https://help.x.com/en/using-x/articles), [공식 API](https://docs.x.com/x-api/articles/introduction).

### 변환과 재시도

- 첫 H1을 아티클 제목으로 분리하고, 없으면 파일명을 사용합니다. 내보내기 창에서 제목을 바꿀 수 있습니다.
- 제목·목록·인용·굵게·기울임·취소선·외부 링크는 X의 본문 형식으로 변환합니다. 코드와 표는 Markdown 블록, 블록 수식은 LaTeX 블록으로 보냅니다.
- 인라인 수식은 `$` 구분자를 제거한 LaTeX 텍스트로 문장 안에 유지하고, 블록 수식은 X 수식 블록으로 보냅니다. 중첩 목록은 평탄화됩니다. 내부 문서 링크는 일반 텍스트로, 이미지는 설명으로 바뀝니다. 이미지는 X에서 직접 업로드하세요. 이미지 URL을 내보내지 않아 마크벡터 이미지에 대한 외부 조회도 생기지 않습니다.
- 같은 창에서 완료된 초안 생성 요청을 다시 보내면 `DATA_DIR/x-articles.json`의 결과를 재사용합니다. 네트워크 오류로 X의 처리 결과를 확인하지 못하면 자동 재시도하지 않습니다. 먼저 X 아티클 목록을 확인한 뒤 재시도하세요. 창을 다시 열면 새 내보내기가 됩니다.
- X의 `429`는 요청 제한과 사용량 상한(`usage-capped`)을 구분합니다. 15분 창(`x-rate-limit-*`)과 함께 `x-user-limit-24hour-*`, `x-app-limit-24hour-*` 같은 `x-*-limit-*` 한도, `x-access-level`, `x-transaction-id`, 사용한 인증 방식(`oauth1` 또는 `oauth2`)을 화면과 서버 로그에 남깁니다. 리셋 시각은 UTC와 KST로 함께 보이며, 24시간 카운터의 남은 횟수가 0이면 그 초기화 시각을 안내합니다. 같은 헤더는 다른 오류 응답에도 남깁니다. 토큰·시크릿과 X 오류 본문 원문은 기록하지 않고, 제한이 풀렸는지 확인하는 재호출도 하지 않습니다.

API는 기존 앱 로그인으로 보호됩니다. `GET /api/x-articles/config`는 설정 여부만 반환합니다. `POST /api/x-articles/drafts`는 `{request_id, title, content_state}`를 받아 초안을 만듭니다. `request_id`는 클라이언트가 생성한 UUID이며, 응답은 `{article_id, url}`입니다. `url`은 X의 아티클 목록 주소입니다.

변환 회귀 테스트는 `python3 -m http.server 8765 --directory frontend`로 정적 서버를 실행하고 `http://127.0.0.1:8765/tests/x-article.html`에서 확인합니다. 백엔드 테스트는 `cd backend && uv run pytest tests/test_x_articles.py`이며 외부 X API를 호출하지 않습니다.

| PUT | `/api/custom-symbols` | 공용 커스텀 심볼 CSV 저장 `{content}` |

`POST /messages`는 줄바꿈으로 구분된 JSON 이벤트를 스트리밍합니다. `user_turn`과 `assistant_turn`은 서로 다른 파일이 아니라 **같은 파일**(`turn.file`)의 두 저장 시점입니다 — `user_turn`은 사용자 부분만 담아 새로 만든 직후, `assistant_turn`은 어시스턴트 부분까지 채워 다시 저장한 직후:

```
{"type": "user_turn", "turn": {"id": "...", "file": "0003.md", "content": "## User\n\n...", ...}}
{"type": "delta", "text": "..."}
{"type": "delta", "text": "..."}
{"type": "tool_status", "status": "running"|"completed", ...}   (일부 프로바이더만)
{"type": "assistant_turn", "turn": {"id": "...", "file": "0003.md", "content": "## User\n\n...\n\n## Assistant\n\n...", ...}}
```

프로바이더 오류 발생 시 `{"type": "error", "message": "..."}` 이벤트가 전송됩니다.

## 새 LLM 프로바이더 추가하기

**OpenAI 호환 API**라면 위의 [OpenAI 호환 프로바이더](#openai-호환-프로바이더-hermes-자체-호스팅-등) 처럼 `.env`에 `CUSTOM_OPENAI_PROVIDERS` 한 줄만 추가하면 되고, 코드 수정이 필요 없습니다.

그 외의 새 API 형식을 통째로 추가하려면:

1. `backend/app/providers/`에 `LLMProvider`를 상속한 클래스 작성 (`stream(messages, model, reasoning_effort=None, system_prompt=None) -> AsyncIterator[dict]`와 `list_models() -> list[str]` 구현. `stream`은 문자열 조각이 아니라 `{"type": "text", "text": ...}`와, 있으면 `{"type": "tool_status", ...}` 이벤트를 yield합니다)
2. `backend/app/providers/registry.py`의 `STATIC_PROVIDER_INFO`, `get_provider()`, `_is_configured()`에 등록

프론트엔드는 `/api/providers` 응답을 그대로 반영하므로 별도 수정이 필요 없습니다.


## 세토 iPhone 실시간 입력

세토 앱의 mark-vector 네이티브 편집창은 로그인 세션으로
`/ws/documents/{project_id}/{conv_id}/{filename}?write=1`에 연결합니다.
아이폰이 유일한 작성자이며 전체 텍스트 스냅샷을 약 60ms 간격으로 합쳐 전송합니다.
서버는 파일 저장을 마친 뒤 작성자에게 `{type:"ack", sequence, version}`을 보내고,
같은 문서를 열어 둔 웹 편집기에 `{type:"update", content, version}`을 보냅니다.
맥에서는 같은 문서를 열어 두면 편집기와 마크다운 미리보기가 바로 갱신됩니다.
이미 열어 둔 웹 탭은 새 코드를 받도록 한 번 새로고침해야 합니다.

구독 연결은 같은 경로에서 `write=1` 없이 열고, 현재 저장 상태를 `ready` 메시지로
받습니다. 재연결도 파일에서 다시 읽으므로 서버 재시작 후에도 저장 내용이 유지됩니다.
새 연결과 각 메시지에서 로그인 세션을 검사하고 외부 Origin을 거부합니다.
문서 내용은 공개 라이브·안경 ambient 채널에 보내지 않습니다.

아이폰은 한 번에 한 스냅샷의 저장 완료를 기다리고 그 사이 입력을 최신 내용으로
합칩니다. 연결이 끊기면 로컬 입력을 유지한 뒤 재연결 시 최신 내용을 다시 전송합니다.
문서당 작성자 하나만 허용하며 여러 작성자의 병합은 지원하지 않습니다. 맥에 미저장
수정이 있으면 웹 편집기는 실시간 스냅샷을 덮어쓰지 않습니다. 기존 HTTP 폴링도
연결 중단 시 보조 경로로 남아 있습니다.
