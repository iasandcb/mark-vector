## 오디오 전사 (화자 분리)

폴더 행의 `⋯` 메뉴 → **오디오 전사 (화자 분리)…** 에서 오디오 파일(m4a/mp3/wav/webm/mp4)을 올리거나 브라우저에서 바로 녹음하면, OpenAI `gpt-4o-transcribe-diarize`로 전사하고 화자를 A, B, …로 구분한 마크다운 문서를 그 폴더에 새 초안으로 만듭니다.

```markdown
# 주간회의

> 2026-10-01 09:00 · 32:14 · 화자 3명 · gpt-4o-transcribe-diarize

**A** `00:00` 안녕하세요. 오늘은…

**B** `00:07` 네, 먼저…
```

- 같은 화자의 연속 구간은 한 문단으로 합칩니다. 화자 이름은 편집기에서 `**A**`를 찾아 바꾸면 됩니다. 문서는 일반 초안이라 그대로 LLM에 보내 요약할 수 있습니다.
- **녹음 언어**(자동/한국어/English/日本語)를 지정하면 도중에 다른 언어로 새는 현상이 줄어듭니다. 기본값은 UI 언어이고, 마지막 선택을 기억합니다.
- API 파일 한도는 25MB입니다. 서버는 24MB를 넘는 파일을 ffmpeg로 모노 16kHz 24kbps Opus(시간당 약 11MB)로 압축해 **한 번에** 보냅니다. 나눠 보내면 조각마다 화자 라벨이 달라지기 때문입니다. 브라우저 녹음은 32kbps(시간당 약 14MB)로 녹음합니다.
- `OPENAI_API_KEY`가 필요합니다. ChatGPT 플랜 경로는 전사 API를 지원하지 않습니다.

## 받아쓰기 (🎤)

편집기 툴바의 🎤는 말하는 내용을 커서 위치에 실시간으로 받아씁니다. 언어 선택 옆 **엔진 선택**에서 고르고, 그 선택은 브라우저마다 기억합니다. 기본은 지금까지와 같이 무료인 내장 음성 인식입니다.

| 엔진 | 쓰는 곳 | 비용 |
|---|---|---|
| 🌐 내장 | Web Speech API가 되는 브라우저의 **마이크**(데스크톱 크롬·엣지, 사파리, 안드로이드 크롬). 파일 재생에는 쓰이지 않습니다. | 무료 |
| ⚡ OpenAI | 실시간 전사 `gpt-live-transcribe`(WebRTC). ⚡를 직접 고른 마이크와 파일. Web Speech도 Soniox도 없을 때의 다음 선택. | 켜 둔 동안 분당 약 $0.017 (`OPENAI_API_KEY`) |
| ✦ Soniox | 실시간 전사 `stt-rt-v6`(WebSocket). Web Speech가 안 되는 마이크의 기본, 그리고 🌐일 때 파일의 기본. `SONIOX_API_KEY`가 있을 때만 나옵니다. | 실시간 시간당 약 $0.12 |

`SONIOX_API_KEY`가 없으면 Soniox는 선택지에 나오지 않고, 동작은 이전과 같습니다. 그 키는 서버에만 있습니다. 받아쓰기를 시작하면 서버가 Soniox에 짧은 임시 키를 받아 브라우저에 넘깁니다(`POST /api/stt/soniox/key`, `usage_type`은 `transcribe_websocket`, 일회용, 새 연결은 60초 안에, 한 세션은 최대 3시간). 브라우저는 그 키로 `wss://stt-rt.soniox.com/transcribe-websocket`에 직접 붙습니다. 오디오는 이 서버를 거치지 않습니다(`backend/app/routers/stt.py`, `frontend/static/js/soniox-stt.js`). 받아쓰기 언어가 한국어면 힌트는 `ko`이고, EN/JA를 고르면 그 언어입니다. 중간 결과는 그때그때 바꿔 보여주고, 확정된 토큰만 한 번 이어 붙입니다.

키는 서버에만 둡니다. Fly에 넣는 방법은 [배포](deploy.md), 로컬은 `backend/.env`의 `SONIOX_API_KEY`입니다. 저장소나 브라우저에는 적지 않습니다.

아이폰에서는 애플이 음성 인식을 사파리에만 열어 두어서, 다른 브라우저(Orion 포함)에서는 Soniox가 설정되어 있으면 Soniox로, 없으면 OpenAI로 마이크가 갑니다. 언어 옆 아이콘과 그 툴팁은 기억해 둔 선택이 아니라 지금 실제로 쓰는 엔진과 요금을 보여 줍니다. 파일을 전사하는 동안에는 그 파일의 엔진을 보여 줍니다. OpenAI는 브라우저가 마이크 음성을 OpenAI로 직접 보내고, 서버는 연결 시작만 중계합니다(`frontend/static/js/realtime-stt.js`). 말이 잠깐 멈추면 그 구간이 확정됩니다. 실시간(과금) 마이크 받아쓰기는 OpenAI든 Soniox든 3분 동안 소리가 없으면 비용을 아끼기 위해 꺼집니다. 브라우저 탭을 바꾸거나 마크벡터 안에서 다른 문서를 열어도 받아쓰기는 끄지 않고, 글은 받기 시작한 문서에만 이어 씁니다. 그 문서 탭을 닫으면 멈춥니다. 아이폰 사파리처럼 탭이 가려지면 마이크나 음성 인식을 브라우저가 멈추는 경우에는 세션을 끊지 않고, 그 탭이 다시 보이면 이어서 받습니다. 가려진 동안에는 브라우저가 소리를 주지 않아 그 구간은 받아 적히지 않을 수 있습니다.

**재생하며 전사**(녹음 목록)는 항상 실시간 엔진입니다. 브라우저 음성 인식은 마이크만 들을 수 있어서, 엔진을 🌐 내장으로 두어도 파일은 Web Speech로 가지 않습니다. 🌐이면 Soniox가 있을 때 Soniox이고, 없으면 OpenAI입니다. ⚡를 직접 고르면 파일도 OpenAI입니다. 전사하는 동안 언어 옆 아이콘은 그 파일의 엔진입니다. 일시정지했다가 다시 재생해도, 위치를 옮겨도 이어서 적습니다. 건너뛴 구간은 적지 않고, 뒤로 옮기면 그 부분을 다시 적습니다. 재생 막대와 녹음 목록의 그냥 재생에는 현재 시각/전체 길이가 보이고, `1:23`, `12:05`, `1:02:30` 또는 초(`90`)를 넣고 이동하면 막대를 끈 것과 같은 자리로 갑니다. 길이를 넘거나 시각이 아니면 옮기지 않고 이유를 보여 줍니다. 아이폰에서도 입력칸과 이동 버튼이 손가락으로 눌립니다. 다른 브라우저 탭으로 가거나 다른 문서를 열어도 재생과 전사는 계속되고, 글은 재생을 시작한 문서에만 쌓입니다. 파일 재생에는 3분 무음으로 끄는 장치를 쓰지 않습니다. 강의 녹음은 그 이상 조용할 수 있고, 파일 길이가 비용의 상한입니다. Soniox 임시 키의 세션 상한은 3시간입니다. 아이폰에서 들리는 소리는 미디어 요소로 나가고 세션은 `playback`이라, 운동 앱의 짧은 음성 안내나 Siri·지도 안내는 유튜브 앱처럼 소리를 잠깐 낮췄다가 원래 크기로 돌아옵니다. 그래도 시스템이 재생을 멈추면, 사용자가 일시정지한 것이 아닐 때 안내가 끝난 뒤 이어서 재생합니다. 녹음 목록의 그냥 재생도 같은 세션이고, 잠금 화면에는 제목이 보입니다. 마이크를 쓰는 받아쓰기·녹음·음성 토론은 `play-and-record`를 유지해서 이 재생 세션이 마이크를 끊지 않습니다. 그동안 전사가 `Request timeout`처럼 끊겼으면 그 위치에서 새 임시 키로 다시 붙습니다. 이미 적은 문장은 다시 적지 않고, 재생이 멈춰 있는 동안에는 keepalive로 연결을 유지합니다.

엔진이 둘 이상 되는 브라우저에서는 언어 선택 옆에 엔진 아이콘(🌐 / ⚡ / ✦)이 나타납니다. 닫혀 있을 때의 아이콘과 마우스를 올렸을 때의 요금은 기억된 선호가 아니라 지금 실제로 돌아가는 엔진입니다. 예를 들어 아이폰 Orion에서 🌐을 골라도 Web Speech가 없으면 아이콘은 ✦(Soniox)로 바뀌고, Soniox 키가 없으면 ⚡로 바뀝니다. 기본 기억값은 무료인 내장이고, ⚡를 고르면 OpenAI가 그대로 쓰입니다. 예전에 ⚡를 고른 브라우저에 저장된 `realtime`은 OpenAI로 그대로 읽습니다. 받아쓰는 중에 바꾸면 새 엔진으로 바로 이어지고, 파일을 재생 중이었다면 그 파일을 새 엔진으로 다시 받습니다. Soniox가 보내는 구간 표시 `<fin>`·`<end>`는 글에 넣지 않습니다. 맥의 크롬에서 BlackHole처럼 시스템 소리를 가상 마이크로 넣을 때는, ✦ Soniox와 ⚡ OpenAI가 그 장치를 음성 통화용 에코 제거·음성 분리 없이 엽니다. 크롬 마이크 설정의 레벨 막대는 장치 자체를 보여 주므로 막대가 움직여도, 페이지가 통화 처리된 스트림이나 앞의 빈 채널만 읽고 있으면 Soniox에는 무음이 가고 3분 뒤에 받아쓰기가 꺼집니다. 채널이 여러 개면 트랙의 채널을 직접 읽어 소리가 있는 것만 섞어 16kHz PCM으로 보냅니다. 크롬이 이 사이트의 마이크로 고른 장치(또는 🎙에서 고른 장치)를 그대로 씁니다. 🌐 내장은 크롬이 잠깐 쉬거나 1분 안팎이 지나면 인식기를 스스로 끊는데, 받아쓰기가 켜져 있는 동안 다시 시작하고 이미 적은 문장은 한 번 더 적지 않습니다. 권한을 거절했거나 장치를 열 수 없으면 그 오류를 보여 줍니다. 공용 수식 말의 왼쪽 열(말)은 Soniox에 문맥 용어로 넘어가 그 말을 알아듣는 데 쓰이고, 기호로 바꾸는 일은 지금까지처럼 받아쓴 뒤에 합니다.

## 음성 토론 (🗣)

문서 화면의 🗣를 열면 왼쪽은 말로 하는 토론이고 오른쪽은 지금 연 문서입니다. 너비 700px 미만(아이폰)에서는 대화/문서 탭으로 나뉘고, 입력은 16px, 버튼은 44px입니다. 마이크는 받아쓰기와 같은 ✦ Soniox 경로입니다(임시 키, BlackHole용 캡처, `enable_endpoint_detection`). 화면에 보이는 글에서는 `<end>`·`<fin>`을 빼지만, `<end>`가 오면 그 말을 툴바에서 고른 모델에 보냅니다. `<end>`가 없으면 기본 1.5초(바꿀 수 있음) 동안 새 확정 토큰이 없을 때 보냅니다. 답이 오는 중에 다시 말하면 그 요청을 취소하고, 이어 말한 것과 합쳐 다시 보냅니다. 지금 보내기와 눌러 말하기도 있습니다. 문서를 고쳐 달라고 할 때만 기존 편집 블록으로 오른쪽 문서가 바뀌고, 바뀐 자리는 잠깐 표시되며, 각 수정은 되돌릴 수 있고 저장은 기존 저장과 같습니다. 음성으로 답하지는 않습니다. 긴 문서는 개요와 해당 구간만 보내고, 오래된 턴은 짧게 줄여 최근 턴만 그대로 둡니다. Soniox는 대략 시간당 $0.12이고, 60분이 되면 마이크를 끕니다. 아이폰에서 다른 앱이 소리를 가져가면 세션을 끊지 않고, 이어하기를 누르면 그래프를 깨웁니다. 브라우저 콘솔의 `[discuss]`에 `<end>`/`<fin>`이 실제로 왔는지 남습니다.

### 수식 받아쓰기

받아쓰는 위치가 `$$` 수식 블록 안이면(리모컨 Y, 안경 ↑, 또는 "수식시작"이라고 말해서 엶) 말한 내용을 AsciiMath로 바꿔 씁니다. 변환기는 [asciimath-markdown](https://github.com/iasandcb/asciimath-markdown)의 `spoken-math.js`(0.3.0부터)이고, [scripter](https://github.com/iasandcb/scripter)도 같은 것을 씁니다.

바꾸는 규칙은 왼쪽 트리 맨 위의 **공용 수식 말**(`S` 배지) 문서 하나에 모두 있습니다. 실제로는 `data/spoken-math.csv`이고, 처음 열 때 기본 어휘(`backend/app/spoken_math_default.csv`)로 채워진 뒤로는 이 파일만 씁니다. 한 줄에 `말, 기호` 하나씩(첫 쉼표 앞이 말, 뒤가 기호라서 `과, ,`처럼 기호가 쉼표여도 됨, 기호가 `\n`이면 수식 안 줄바꿈, `$$`이면 `$$`를 친 것처럼 수식 블록을 열거나 닫음, `{1}`·`{2}`가 들어 있으면 순서를 바꾸는 말 — 아래 참고), `#`로 시작하는 줄은 주석, 같은 말이 여러 번 있으면 아래쪽이 이깁니다. 저장하면 바로 다음 받아쓰기부터 적용되고, 다른 브라우저에서도 받아쓰기를 시작할 때 새로 읽어 옵니다. 로그인 없이 읽을 수 있는 `/api/public/spoken-math`로도 공개되어, [scripter](https://github.com/iasandcb/scripter)가 실행할 때 최신 규칙을 받아 갑니다(쓰기는 로그인 필요).

기본 어휘는 [obsidian-publish-asciimath의 kor-math.js](https://github.com/iasandcb/obsidian-publish-asciimath/blob/main/kor-math.js)를 옮겨 온 것에, 소리 내어 말하기 좋은 괄호 말을 더했습니다.

| 말 | 기호 |
|---|---|
| 수식시작 / 수식끝 | 받아쓰는 자리에서 수식 블록을 열기 / 닫기 (리모컨 Y와 같음) |
| 열고 … 닫고 | `(` … `)` |
| 집합 열고 … 집합 닫고 | `{` … `}` |
| 행렬 열고 … 행렬 닫고 | `[` … `]` |
| 다음줄 | `;` (행렬의 다음 행) |
| 영 일 이 삼 사 오 육 칠 팔 구 (공) | `0`~`9` |
| 자연상수, 오일러 | `e` |
| 이고 | 수식 안에서 줄바꿈 |
| A 분의 B | `B / A` (분수, 분모를 먼저 말함) |
| A 오버 B | `A / B` |
| A 에서·부터 … B 까지 | `_ A … ^ B` (적분·합의 아래·위 끝) |
| 시그마 / 소시그마 | `sum` (Σ) / `sigma` (σ) |
| A 으로·로 | `-> A` (극한) |
| 리밋 … 갈 때 | `lim _ ( … )` ("리밋 엔 무한대로 갈 때" → lim₍ₙ→∞₎). 아래첨자 없는 lim은 "극한" |

예: "엑스 승 2 더하기 라지 와이 는 열고 에이 과 비 닫고" → `x ^ 2 + Y = ( a , b )`, "행렬 열고 1 과 2 다음줄 3 과 4 행렬 닫고" → 2×2 행렬.

- 가장 긴 말부터 맞춥니다("라지에이"는 `A`, "집합 열고"는 `{`). 인식기가 한국어 띄어쓰기를 들쭉날쭉하게 하므로 한글 사이 띄어쓰기는 무시합니다.
- 숫자·영문처럼 이미 기호로 받아쓴 것은 그대로 두고, 인식기가 붙인 문장부호(끝의 `.` 등)는 지웁니다(`3.14` 같은 소수점은 유지).
- 인식기가 "에프"·"엑스"를 글자 그대로(`F`, `X`) 적는 경우가 있어, 따로 떨어진 대문자 한~세 글자는 소문자로 바꿉니다(`F(X)` → `f(x)`, `DX` → `dx`). 대문자는 "라지" 뒤에 올 때만입니다("라지 F" → `F`). `sin`처럼 소문자가 섞인 말은 그대로 둡니다(`RR` 같은 기호는 어휘에서 나오므로 영향 없음).
- 한국어는 분모를 먼저("삼 분의 일"), 경계의 조사를 뒤에("영에서") 말해서 AsciiMath와 순서가 다릅니다. 그런 말은 기호에 `{1}`(바로 앞 덩어리)과 `{2}`(바로 뒤 덩어리)를 써서 순서를 바꿉니다: `분의, {2} / {1}`, `에서, _ {1}`. 덩어리는 토큰 하나 또는 열고~닫고로 묶은 괄호 하나이고, 바꾼 결과도 한 덩어리가 됩니다. 예: "적분 영에서 삼 분의 일 까지 엑스 승 이 디엑스" → `int _ 0 ^ ( 1 / 3 ) x ^ 2 dx`, "극한 밑 열고 엔 무한대로 닫고 …" → `lim _ ( n -> oo ) …`. 받아쓰기는 구절 단위로 바뀌므로 "삼 분의 / 일"처럼 그 사이에서 쉬면 짝이 이어지지 않습니다.
- 대문자는 "라지"로 말합니다("라지 에이" → `A`). 원본의 "빅"은 뒤 모음과 연음되어("빅 에이" → [비게이]) 인식이 잘 안 돼 바꿨습니다.
- 원본에서 변수 `e`·`o`였던 "이"·"오"는 숫자 2·5로 바꿨습니다(수식에서는 숫자가 훨씬 흔함). `e`는 "자연상수"나 "오일러"로 말합니다.
- 원본 목록과 다른 점: "피"가 두 번(`p`, `phi`) 있어 나중 것인 `phi`로, "집폐"는 `{`로 잘못 적혀 있어 `}`로 바로잡았습니다.
- 지시문이 없어 LaTeX로 읽히는 문서라도 아직 다른 수식이 없으면, 처음 수식을 받아쓸 때 맨 위에 `<!-- math: asciimath -->`를 넣습니다. 이미 LaTeX 수식이 있거나 `<!-- math: latex -->`라고 밝힌 문서에서는 바꾸지 않고 일반 받아쓰기로 둡니다.
